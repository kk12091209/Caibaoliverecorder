# 菜包下载助手

当前代码入口：前端 `src/features/downloader/`，后台 `server/downloader/`，测试 `tests/downloader/`。下方按日期记录行为与验证历史；提及的部署归档和验收附件不纳入公开源码，生产状态以实际部署为准。

运行环境：Node.js 22.18+，已安装 Chrome。B 站音画合并需要 FFmpeg / FFprobe；当前开发机自动复用相邻录包机项目中的工具，也可通过 `FFMPEG_PATH` / `FFPROBE_PATH` 指定可执行文件。

```sh
npm ci
npm run dev:downloader
```

打开 http://127.0.0.1:17970/tools/downloader 。端口可通过 `DOWNLOADER_PORT` 调整。`npm run dev` 只运行原网站前端；下载工具需要上述带本地解析服务的入口。当前仅绑定 127.0.0.1。

## 功能

- 抖音 / B 站完整视频链接、短链、整段分享文字。
- 小红书接入已在本地实现，尚未上线或通过匿名网页入口验收。支持单篇笔记完整链接、xhslink.com 短链及分享文字，保留签名参数；图片源和下载任务沿用现有图集流程。实际可用性受匿名详情页访问限制影响，详见下方记录。
- 抖音视频使用无水印播放源，按可获取的分辨率和码率选择；不做放大转码。
- 抖音图文按作品实际返回数量显示缩略图，支持大图弹窗、左右切换、单图下载、多选、全选及 ZIP。下载保留原始分辨率：已有 JPEG/PNG 保留原字节，其他普通图片转高质量 JPG（95、4:4:4），含透明通道的图片转 PNG；不把缩略图作为下载图片。图片输入保护为 40 MiB / 4000 万像素。
- 预览优先从平台图片 CDN 直接加载，使用 no-referrer；失败时回退同源代理，列表回退图缩至 360px，弹窗回退仍提供完整图片。代理原图、缩略图和转换结果共用最多 64 MiB、十分钟内存缓存，不写 COS。
- 图文按四个网络任务并发获取，转换限制为单个任务以控制内存。B 站音画并行获取；支持 Range 的大文件使用三个分段、精确长度校验后保存，遇到不支持的响应自动回退普通下载。所有视频均以 MP4 重新封装，不降低分辨率或重编码。
- 成功解析结果短暂缓存五分钟；页面轮询不会在每次任务更新时中断并重复发出请求。
- B 站从任意分 P 链接识别完整投稿；默认勾选链接对应的 P，支持修改选中项。多选分 P 分别下载为 MP4，不再打包 ZIP；每个文件完成准备后即可传输，不等待其余分 P。
- B 站和抖音普通视频只展示封面、信息和下载操作，不提供站内视频预览，也不因查看解析结果准备整段视频。图文大图和实况查看保留原流程。
- 点击下载后请求浏览器原生下载；多选分 P 保留各文件的单独下载入口，浏览器拦截连续下载时可逐个点击。多选时点击整张图片切换勾选，普通状态点击才打开预览。
- Windows / macOS 的桌面 Chrome、Edge 自动使用三路分段传输。独立 Service Worker 把有界、按顺序校验后的字节流交给原生下载列表，不先把整个文件加载成 Blob。分段停滞、截断或连接错误最多重试两次；范围、长度和文件版本不匹配会中断，不拼接错误文件。手机、Safari 或后台能力不可用时继续普通下载。
- 公网成片由 Caddy 在每次验证匿名会话归属后直接传输，支持 HEAD / Range / If-Range；源文件准备、JPG / PNG 转换和 MP4 合并仍在下载服务完成。普通视频与 ZIP 下载先返回附件响应，再传输准备好的真实字节；单张图片等待确认 JPG / PNG 格式后开始传输。不上传 COS。
- 成片目录独立挂载为 `/srv/caibao/download-cache`，网站根目录无法直接访问。服务根目录只有遍历权限，文件地址只由鉴权服务按已登记文件映射；不要增加目录浏览或通配静态映射。
- 抖音公开分享页未返回完整数据时，使用本机独立的匿名 Chrome 上下文加载作品；不读取日常浏览器的 Cookie 或登录资料，也不自动处理验证码。

## 当前边界

- B 站使用匿名游客播放参数 `qn=80&fnval=4048&try_look=1`，优先获取 1080P，按实际返回的视频流选择最高可用分辨率。不能把顶层 `quality` 或 `support_formats` 清晰度列表当成已经取得的视频流。原视频或可用流较低时保留实际画质，不放大转码。目前不接入、读取或保存 B 站登录信息，不使用 `BILIBILI_COOKIE`；更高画质的账号授权留待后续需求。
- 抖音临时限制访问时会明确报错，可以重新解析。私密、已删除或平台未返回媒体的作品不生成伪造下载地址。
- 小红书优先读取公开页面的目标笔记数据，再尝试独立的匿名浏览器上下文；不导入用户日常浏览器 Cookie，不接入共享登录账号，不执行页面脚本来解析序列化数据。需要登录、验证码或媒体未返回时明确报错。作者嵌入素材的水印会保留。
- 当前只支持 B 站视频分 P；合集中的独立投稿不会被当成分 P 自动下载。

## 多分 P 分别下载（2026-10-27，本地）

- 多选 B 站视频使用 `delivery: parts`，仍只占一个受限任务。返回各 P 的 MP4 文件名和下载地址，分别建立浏览器任务；不创建 ZIP，也不按分 P 数量重复创建后台任务。
- `GET /jobs/:id/stream?part=:index` 先返回该 P 的附件响应，待该 P 的标准 MP4 完成后传输真实字节。后续分 P 未完成或失败时，已完成文件仍可下载；未完成的失败文件可单独重试。HEAD / Range 等待对应文件完成后转到现有鉴权文件路由。
- 附件响应声明 `Incremental: ?1`，Caddy 的 `encode` 排除 `/jobs/*/stream`，避免压缩中间层等待正文而扣住响应头。没有填充字节、虚假长度、整文件 Blob 或新增账号授权。
- 页面说明浏览器可能询问多文件下载权限，并保留逐个下载链接；网页只描述“已请求”，不据此宣称浏览器已接受。普通图片多选仍按原方式打包 ZIP，相册和单 P 流式下载保留原流程。实际平台网络传输与单 P 音画合并仍需要时间。

## iOS 相册与长视频传输（2026-10-21）

- 只有 iPhone / iPad 显示保存方式选项，默认“保存到相册”，可切换为下载文件（兼容 iPad 请求桌面网站）。Android、Windows、Mac 等设备只提供普通下载，不展示相册按钮、选项、弹窗及提示。相册模式保留单独的 JPG / PNG / MP4，不生成 ZIP。文件传到设备后，必须由用户再次点击“打开系统保存菜单”，在一次新的用户操作中调用 Web Share Files，避免 Safari 的用户激活超时。
- 系统菜单是否提供“存储图像 / 储存视频”由操作系统、浏览器及文件兼容性决定。分享 Promise 完成不能证明已保存到相册，界面不会宣称保存成功。失败、取消或不支持时保留文件下载链接及系统“文件 → 共享”说明。
- 相册传输每组最多 10 个文件、128 MiB；100 张图片分组处理并保留选择顺序。单个超出 128 MiB 的视频走浏览器原生下载，再从系统文件共享，避免把长视频完整加载到移动网页内存。
- 单个 B 站视频的 `delivery: stream` 使用经过 DNS / 跳转校验的 Node 网络流，经管道交给 FFmpeg，无重新编码地输出 fragmented MP4。`GET /jobs/:id/stream` 在完整视频完成前输出字节；磁盘缓存为有界分块读取，不在内存缓冲整段视频。仍选择当前访问权限下最高画质。多分 P ZIP、相册及预览保留标准 MP4 完整准备流程。
- 传输中的连接失败会关闭响应，不把半个视频当作完成；任务失败会清理临时文件。HEAD / Range 等待完整文件后重定向到现有 Caddy 文件路由，保留所有者校验、断点续传和临时文件过期清理。已完成任务也重定向到原文件路由。

## 桌面代理线路适配（2026-10-21）

- 用户在同一 Windows Chrome 中关闭代理后速度明显改善，确认代理路径是本次慢速的重要因素；无需要求用户永久关闭代理。三路传输用于改善单连接慢速，不能突破代理总带宽限制，也不能保证所有代理都会提速。
- `downloader-transfer-worker.js` 只注册 `/api/downloader/` 范围，仅处理带 `parallel=1` 的合法同源文件地址。每个分段仍携带原匿名会话并通过服务端归属校验，不引入跨域媒体转发、浏览器媒体缓存或 COS 上传。
- 默认分段最小 1 MiB，按文件大小调整；公网 1 GiB 限额内最多 64 段。最多预取三段，每段最大 16 MiB，停止消费时不继续无限预取。下载取消会停止全部分段；浏览器断点续传直接交给已有鉴权 Range 服务。
- 单个 B 站视频先沿用原有边合并边传输，在成片完成后从已经输出的准确字节位置切换并行读取，不重复前缀，也不等待整个视频合并才开始下载。状态查询失败时保留原流式传输。
