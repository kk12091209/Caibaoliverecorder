# 完整成片导出优化与验证（2026-10-24）

本轮只在本地开发和验证，没有提交、推送、安装包发布或网站部署。基线为本轮开始时的完整工作副本，包含此前未发布的录中预处理、缓存、排版和预览优化，**不是 Git HEAD 或线上 v0.2.7**。

## 导出流程

- `server/export-plan.js` 共用导出时间线及来源复用判定；纯净版和弹幕版统一经过 `Media.publishFiles()` 保存已完成 MP4，沿用原有发布凭证、取消、失败保留和重试保存机制。
- 整场纯净版允许把经过检查的多段 H.264/AAC 录像直接封装。片段间按明确时长连接，保持既有“整场略过真实断流空缺”的行为。不会为了拼接而补造缺失画面。
- 首个视频关键帧晚于片头音频、不超过 100 ms 时，完整来源读取从已封口的第零片段保留音频，验证首个视频包确为关键帧。原来的关键帧裁剪读取保持原语义；独立音频处理与精确选段不因此放宽规则。
- 双文件导出复用已有弹幕视频块，同时直接封装纯净视频，将其 AAC 音轨用于弹幕 MP4，省去整场 FLAC/AAC 再处理。临时纯净结果就是本次最终输出，不另建长期纯净视频缓存。
- 来源编码头历史、尺寸、帧率或编码参数不兼容，以及需要绘入连麦昵称/头像时，保留原有编码。精确剪辑继续使用原有边界处理及完整缓存块复用，尚未引入首尾 GOP 的智能重编码拼接。
- 多段复制结果逐段核对编码签名、帧数、时长与音轨数量，拼接后再次核对。纯净版复制失败先选择实际可用编码器，整份重建，避免混拼不兼容编码。双文件的原画面封装失败保留已验证弹幕块；明确 AAC 封装错误只修复音频。

弹幕排布、条数、字号、字体、输出分辨率、弹幕视频帧率和编码画质参数保持既有设置。纯净版复制的是原始压缩码流，避免一次有损重编码，文件体积可能比原先重编码结果更大。

## 测量方法

使用本机 Apple M5、10 核、16 GiB，Node 24.12.0、FFmpeg 9.0.2、VideoToolbox 硬件编码与固定 Noto Sans CJK SC 字体。同一份动态 `testsrc2` 1080p30 H.264/AAC 输入，取 120 秒并作为两个来源，形成约四分钟有效录像和中间五秒真实空缺；每秒三条中文弹幕，弹幕输出为 1080p60，缓存块 60 秒。

修改前 → 修改后 → 修改后 → 修改前，每版两次，独立数据库和媒体工作目录，媒体任务串行执行，没有同时运行回归套件，也没有主动清空系统文件缓存。素材创建、导入、字体导入及输出验证在计时之外；从创建导出任务到完成最终 MP4 发布的等待纳入计时，包括本次任务需要的探测、音视频处理、封装和保存。预处理单独计时，再与双文件导出相加，代表尚未准备时的全部媒体工作。

纯净版包含原始 30 fps 画面；弹幕版包含现有 60 fps 画面。两种模式不强制采用相同的画面编码路径。对照中的纯净版画质由原来的有损重编码改为保留原码流，不能用“与旧有损成片逐像素相同”作为质量目标。

## 正确性与稳定性

新增独立多来源用例核对全部解码帧、AAC 包字节、单调解码时间戳和重连处的音频延迟。21 ms 起播偏移另覆盖单来源、多来源和原片整理后的直接读取，音频包比较遵循导出的半开时间区间；恰好开始于区间终点的包不属于所选范围。精确剪辑、参数变化、无声来源、连麦标注、复制失败、AAC 拒绝、取消与来源读取租约一并回归。

性能对照还核对所有输出的尺寸、编码、帧率、帧表与音画时长，解码检查首尾和重连边界；双文件的两条音轨逐字节一致。修改前后的弹幕成片在相同时间点抽样像素摘要比较。短样本抽帧验证不等同于对四分钟成片逐帧全量比对，逐帧比对由小型独立正确性用例承担。

完整套件首次运行暴露了原有看门狗测试对进程启动的 100 ms 假设；独立运行通过。测试的正常进度阶段改为 500 ms 期限并持续超过两个期限，仍验证每次进度会续期；冻结计数阶段继续使用 100 ms。产品原有 120 秒无进展期限保持不变。

最终完整回归以文件并发 4 运行：**859 项，855 通过、0 失败、4 项环境跳过**，约 77.6 秒。新增 12 项真实来源导出验证全部执行；原有 FFmpeg 边界、预览/导出、字幕、音频、取消与保存恢复检查也执行。四项跳过为 Windows 路径专属用例、两项未配置的真实录制核心集成用例及源码包环境用例。前端生产构建、`git diff --check` 通过；没有增加第三方依赖。

默认高并发整套的一次运行还遇到既有后台退出用例的 10 秒等待超时；独立复核的 exit/quit 分别约 1.10 / 0.12 秒，最终受控并发全套也通过。保留对应日志，没有据此修改产品退出流程或放宽该用例。新增原片整理读取用例首次漏建 `source_storage` 测试登记，补齐隔离测试设置后通过。此前失败不计作最终通过，完整记录均保留。

验证后，当前 `server/` 与 `shared/` 的 SHA-256 和正式性能对照使用的冻结候选一致。证据目录包括 `before/`、`after/`、`after-hashes.json`、`benchmark/report.json`、逐轮报告、`full-verified.log`、`focused-last.log` 与 `build.log`。本轮没有启动用户的真实录制，也没有修改网站代码、运行时用户数据或 Git 提交。

## 第二轮：单独弹幕版与精确剪辑

本节以第一轮完成后的本地代码为基线，再与本轮候选做对照，不能将两轮百分比相加。本轮仍未提交、推送或部署。隔离证据位于 `/private/tmp/caibao-clip-audio-20261024/`，其中 `before/` 是开始修改前的副本，`after/` 是正式对照使用的冻结候选。

### 减少重复处理

- 单独整场弹幕版在验证完整 AAC-LC 来源的配置、连续时间戳、采样率、声道、包数、起点和累计时长后，直接复制音轨。多个来源的前置静音、内部缺口或不兼容配置仍退回精确修复，不把断流静音省掉。无需为单独弹幕版额外生成纯净 MP4，也不建立长期音轨缓存。
- 必须修复或精确裁剪的音频，输入保留原有时间戳，只传音频包给 FFmpeg；依旧按样本裁剪、补静音和统一 FLAC 中间块后编码一次 AAC，没有改成按 AAC 包粗切。
- 精确弹幕剪辑不再把整个不足 60 秒的缓存边缘当成缺口。验证缓存的实际关键帧、恒定帧率、无 B 帧及精确 PTS/DTS，从下一个可独立解码的关键帧开始，复制结束前最后一个关键帧之间的完整区间；首尾从原片重绘，避免对已有弹幕画面二次有损压缩。
- 每次复制后再次核对帧数、零起点、时长及编码签名。复制失败只重绘受影响区间；整体编码签名不兼容仍完整回退。没有缓存、切片过短或缓存与当前样式不一致时沿用原处理。
- 保持 RENDER_VERSION 9、原编码质量参数、分辨率、帧率、弹幕字体/字号/条数和共享排版规则。没有扩大并发、后台资源预算、长期视频缓存或引入依赖。

### 同机对照

整场旧版的波动主要位于音频阶段：2.648 / 5.951 秒；新版直接复制为 0.970 / 0.654 秒，画面和音频均没有新增有损编码，四个缓存块全部复用。即使取旧版最快与新版最慢对照，本样本的整场等待仍缩短约 33%；63.59% 是两轮均值，不代表所有设备的固定收益。后台准备耗时 52.348 / 53.992 → 53.326 / 53.690 秒，基本没有变化。没有缓存时，不能把已经准备好的导出提速理解为首次总耗时也缩短六成。

精确剪辑的两轮新版均实际复制 28 秒、只重绘 2 秒首尾；双文件的纯净画面仍需原有编码，所以整体收益小于单独弹幕剪辑。纯净版精确剪辑本轮没有引入对播放器兼容性有风险的隐藏前滚帧或不兼容码流混拼，因此不宣称提速。画面编码进程数量从一次变为两次短边缘编码，不表示实际编码量增加；应看重绘秒数及最终完成时间。

### 长录像估算与适用边界

按本轮四分钟样本的两轮均值线性换算，**仅指已经完成预处理后的整场单独弹幕版**：两小时约 2 分 30 秒 → 55 秒，三小时约 3 分 45 秒 → 82 秒。旧版波动较大，且此换算包含每次启动、探测和发布的固定开销，不是两/三小时实录保证；硬盘、AAC 连续性及缓存是否命中都会改变结果。若需要先做完整预处理，改善约为本机样本中的 4.9%，仍以绘制耗时为主。

精确剪辑应按选段总长度、实际缓存命中和关键帧位置估算，不能只看原直播有两小时还是三小时。本次 30 秒片段节省约 5.21 秒（弹幕版）或 5.23 秒（双文件）；批量选择类似片段时可累加参考，但很短、冷缓存或不同帧率的结果不能照搬。

### 画质与稳定性验证

两轮新版精确弹幕剪辑都将复制的 28 秒、**1,680 帧 1080p 画面全部解码取摘要**，与对应缓存逐帧一致。整场弹幕版的首尾和重连边界抽样与旧版完全一致。精确剪辑与旧版重新起始 GOP 的成片在首尾及接缝附近抽样比较，160×90 灰度样本最大 MAE 0.0836、最低 PSNR 58.54 dB；此抽样不是对首尾全分辨率的客观画质评分。首尾采用与原来相同的编码器和质量参数，中间直接保留已验证码流。所有输出核对尺寸、帧率、时长和音画轨道，接缝附近解码成功，双文件音轨相同。

新增真实 FFmpeg 用例覆盖：60/30 fps 精确帧边界、重连后的非零全局起点、缓存复制失败仅重绘对应区间、样式变化不复用旧画面、前置 AAC 保留、多来源 AAC 包内容不变、内部音频缺口/重连前置静音修复、取消后进程与来源/缓存租约全部释放。精确音频仍沿用既有 PCM 静音和切点检查。

复现本节对照：

```sh
node scripts/benchmark-export.mjs \
  --suite cached \
  --before /absolute/path/to/second-round-before \
  --after /absolute/path/to/frozen-candidate \
  --source /absolute/path/to/source-1080p.flv \
  --seconds 120 \
  --sources 2 \
  --output /absolute/path/to/new-result-directory
```

`cached` 套件需要至少 34 秒输入，以验证同一个 30 秒精确剪辑和全部 1,680 复用帧。`benchmark/report.json` 包含每轮任务阶段、实际复用/重绘时长、音轨复制状态、编码命令数量、质量比较与长录像估算；不能只依据编码命令次数判断速度。
