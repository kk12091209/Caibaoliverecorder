# 未预处理长视频导出：本地并行调整（2026-10-25）

用户授权录播机只在本地调整。本轮没有制作安装包、替换 Applications 中的已安装程序、推送或发布录播机；网站下载助手的独立上线见网站 docs/DOWNLOAD-LATENCY-20261025.md。

## 改动

过去，硬件导出同时最多绘制两块；解码与 ASS 弹幕处理仍消耗 CPU。对已封口长素材，在至少四个未完成块、Apple VideoToolbox、至少八核和足够内存时，前台现在允许三至四个独立块并行，最高四个。每块参数、分辨率、帧率、弹幕数量、字号、编码质量和缓存签名保持原值。其他硬件沿用两路，软件编码沿用单路。

- 内存按分辨率估计每个 worker 的缓冲，额外保留 2 GiB；缺失/异常资源信息不扩容，4K 要求比 1080p 高。
- 调度器只在当前前台批次期间开放扩展容量，结束、出错或取消时恢复。交互预览仍有可用名额，后台预处理上限不增加。
- 开始导出时正在录制则只用单路。导出途中开始录制时不再补充扩展名额，正在运行的块完成后收敛到录制期间的限制。
- 硬件会话不足时，等全部同批子任务结束后从四/三路降到两路，再降到单路，保留已验证完成的块；用户取消、空间/权限错误不触发降档重试。
- 任务记录 `foregroundRenderWorkers`。多个独立选段仍作为独立任务按既有顺序处理，没有把整个任务队列一起并发。

代码：server/foreground-render-policy.js、server/media-scheduler.js、server/media.js、server/render-plan.js；新增 test/foreground-render.test.js。

## 本机观察

先用相同 FFmpeg 参数处理六个 12 秒块，按 2→3→4→4→3→2 运行，72 秒素材总量的两次耗时：

| 并发块数 | 两次耗时 |
| --- | ---: |
| 2 | 37.615 / 47.018 s |
| 3 | 33.634 / 31.194 s |
| 4 | 27.058 / 29.969 s |

另外试过加解码/滤镜线程、硬件解码，没有得到稳定改善，未将这些参数改为默认值。

完整冷导出对照使用原有隔离基准：Apple M5、10 核、16 GiB，固定字体，1080p30 H.264/AAC 合成素材两个来源，共 239.976 秒，含一次重连间隔；每秒三条弹幕，纯净版 30 fps、弹幕版 60 fps。计时从入队到两份完整 MP4 保存完成，源文件生成、导入、验证不计时。预处理缓存为零，输入有效画面均完整绘制；纯净视频和 AAC 仍复用原编码。

| 版本 | 两轮冷导出耗时 | 两轮平均 |
| --- | ---: | ---: |
| 修改前，2 路 | 206.073 / 106.623 s | 156.348 s |
| 本地候选，4 路 | 129.588 / 99.717 s | 114.652 s |

按平均值计算等待减少 26.67%，但**不能据此承诺稳定快 27%**。本机有其他高负载任务，load average 一度超过 200，第一轮旧版本和最后一轮旧版本相差很大，两版范围重叠；本轮回归也曾与基准并行执行。这是有方向性的短样本观察，不是受控性能实验。不得套用昨天空闲环境的 55 秒基线，也不使用脚本报告中的两/三小时线性外推值作为长录像实际结果。尚未实测两/三小时真实录像、Windows 实机或持续散热影响。

## 正确性与回归

- 完整对照四轮均校验 H.264、1920×1080、纯净版 30 fps / 弹幕版 60 fps、输出时长、音轨和首尾/分块/重连附近解码。
- 两份输出的 AAC 摘要一致；前后两轮各 13 个缩小灰度画面抽样均一致（最大 MAE 0）。属于抽样核对，不是全片逐帧验证。
- 新前台资源/并发/回退/取消 6 项、既有闲时处理与调度 9 项，共 15/15。
- 真实 FFmpeg 的缓存精确剪辑、冷导出、导出取消及两种路径的 SIGKILL 恢复共 34/34。取消保护补充后，导出控制 4/4 复跑通过。
- 首轮媒体测试因默认 TMPDIR 包含 macOS 软链接而被既有安全检查拒绝；改用 TMPDIR=/private/tmp 后全部通过。没有放宽产品的目录保护。
- 性能采样后补齐异常总内存信息的保守降级，并增加 AbortError 的明确拦截；成功路径的绘制、编码、音轨参数未变。
