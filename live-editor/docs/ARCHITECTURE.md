# 项目结构与维护边界

源码 `live-editor` 是修改和构建的唯一入口。安装目录中的 `程序组件/live-editor` 是运行产物，不应作为另一份源码维护。修改后先测试、构建，再同步后台模块和 `dist`；发布脚本也从同一份源码取文件。

## 目录

| 目录 | 用途 |
| --- | --- |
| `src/` | Vue 页面、时间定位、弹幕预览及桌面桥接；`api.js` 统一本机 API 请求 |
| `src/components/` | 时间轴、缩放与拖动标记、弹幕 Canvas |
| `server/` | 本机 HTTP 服务与业务模块；运行时仅依赖 Node 内置模块 |
| `desktop/` | Windows 窗口、托盘、本机服务生命周期与运行组件解析 |
| `installer/` | 中文安装与卸载向导及翻译许可 |
| `scripts/` | 隔离开发入口、构建、源码打包、发布与验证工具 |
| `test/` | Node 测试和合成媒体夹具，使用独立临时目录 |
| `docs/` | 维护、构建和发布说明 |
| `dist/` | 生成的页面，仅最新入口及其资源用于发布，不纳入源码仓库 |

## 后台职责

`index.js` 创建服务、注册路由和维护定时器。具体工作交给以下模块：

| 模块 | 职责 |
| --- | --- |
| `recorder.js`、`bilibili-rooms.js`、`local-endpoint.js`、`service-runtime.js` | 连接录制核心、持久保存 B 站房间启停状态、本机地址与服务实例管理 |
| `multi-platform-recorder.js`、`room-lookup.js`、`douyin-room.js`、`douyin-recorder.js`、`douyin-flv.js` | 链接平台识别、数字房间号核对及主播选择；抖音房间监控、直写原片与时间戳规范化；B 站下载保持原核心 |
| `douyin-chat.js`、`douyin-chat-worker.js`、`douyin-websocket.js`、`douyin-protocol.js`、`douyin-signing.js` | 有界 IPC、独立线程解析、WebSocket 保活/重连、最小 protobuf 解码和本地签名 |
| `chat-intake.js`、`chat-rules.js`、`lottery-activities.js` | 每房间独立配额、共用长消息/同文规则、分批索引、活动口令与有效窗口 |

| `media.js`、`export-encoding.js`、`export-publication.js` | 手动导出队列、编码/码流复制、成片可靠保存及重试 |
| `export-checkpoints.js`、`media-retry.js` | 导出步骤落盘、异常退出后校验复用、临时读写故障的有限重试 |

| `idle-render-policy.js` | 闲时块并发的资源门槛、按素材吞吐试验及保守回退 |
| `live-preparation-policy.js`、`live-recording-health.js`、`live-system-resources.js` | 录中提前处理的运行预算、实际录制推进、写盘/索引/事件循环健康与接电/热状态准入 |

| `temp-workspaces.js` | 按素材及进程归属管理临时工作文件 |
| `waveform.js`、`density.js`、`chat-filter.js` | 音频波形、弹幕密度、抽奖及表情包占位过滤 |

保持平铺后台模块，是因为运行包和服务构建标识直接收集 `server/*.js`。若将模块搬入子目录，必须同时更新桌面构建标识、发布白名单和验证脚本，不能只移动文件。

删除、导出保存和临时目录模块共用 `storage-files.js` 的路径归一化与目录包含判断；各操作自己的身份、引用、符号链接检查与错误信息仍由所属模块维护。弹幕预览背景使用无损 WebP，前端和 FFmpeg 共用同一文件，保持原尺寸与像素；构建后的预览加载器也兼容旧 PNG。

预处理对已有成片的核对使用当前数据库连接内的临时变更队列，跟踪素材、编辑和导出记录变更，事务回滚也回滚队列。不新增持久业务数据；启动时重建待检查队列，每轮最多处理 25 份素材。未改变的历史素材不再逐条读取导出记录。用户在程序外删除成片无法触发数据库变更，因此完整成片另有分批巡检，每轮巡检结束后等待 30 秒；手动排队的素材在编码前仍会核对，避免重复压制。导出按素材、状态、创建时间建立索引，素材来源按所属素材及时间建立索引。

`src/state-sync.js` 统一管理界面状态推送、断线轮询、请求取消与旧响应隔离。推送正常时不定时请求完整状态；连接出错或 6 秒未收到消息时使用 2.5 秒轮询，并恢复推送。正在录制、整理中的选中素材仍每 2.5 秒更新详情；已完成且元信息完整的素材详情降为 30 秒检查，显式操作可立即刷新。一次广播为所有窗口复用同一份状态序列化结果。

## 媒体调度与复用

FFmpeg、FFprobe 与波形解码共用 `MediaScheduler`。正常最多 3 个任务，其中非交互任务最多 2 个；录制期间总数降为 2，非交互最多 1 个，普通后台预处理不启动。仅通过独立安全准入的 `live-background` 可以在录制期间运行一个任务。预览/波形优先于手动导出，手动导出优先于后台工作。该队列不包含直播录制核心，也不会中断正在写入的原片；紧急退让只取消预处理进程。

录中提前处理是本地开发版的独立默认关闭开关，受自动预处理总开关控制。首版只在单路录制、真实字节与媒体时间持续推进、索引/写盘健康、接电且系统热状态与内存正常、实际硬件编码可用时准入。macOS 使用独立的只读小助手采样电源与热状态，不在录制期间编译；其他平台或未知信号保守回到录后处理。原片写入不等待预处理，录中最多一个工作任务，保留约 90 秒尾部，仅处理完整的 60 秒封口块。

录中每 60 秒约分配 18 秒实际处理时间，不能解释为 CPU 占用 30%。初次需约 30 秒健康观察；任务超出预算后延长休息，正常预算不足不丢弃已开始的块。录制停滞、严重热/内存压力、写入和索引异常时取消后台任务，等待退出后冷却 60/120/300 秒；同场反复异常停用提前处理。健康检查持续运行；等待新完整块时按素材时间门槛停止重复探测，其他资料未就绪时短暂退避。录制结束后交回既有闲时策略，立即核对并补齐尾部。切换设置、剪辑、弹幕和连麦资料变更仍需验证缓存。

新封口片段保存内容摘要、文件身份、关键帧摘要与历史编码头；旧范围身份不包含增长中的文件长度或存储模式。经字节和定位索引验证的 `chunks → direct` 整理保持同一区间身份。旧素材不能证明身份时保留原保守路径。编码头切换先封口，读取历史块使用对应编码头；首版录中遇到混合编码区间暂缓。缓存发布前核对完整的标准弹幕布局；顺序追加可使用下述增量检查点，迟到弹幕、防重复过滤回撤和昵称/头像变化按实际影响使缓存失效；仅延长连麦未来结束时间不会误伤过去块。录中只检查既有独立连麦索引，不主动追读整份文件。

已经完成并通过 MP4 完整性检查的片段，若发布核对仅因索引暂时未就绪而等待，可以进入独立的待验证区。它不是缓存命中，不提供读取租约，不参与导出；后续同签名请求重新核对来源、样式、弹幕、连麦资料及文件身份，通过后直接发布原像素。真实变化仍丢弃并重绘。待验证结果全局最多 2 个、256 MiB、绝对期限 120 秒，仍计入缓存磁盘预留；等待不持有编码进程。暂停、关闭开关、取消素材和退出会清理，过期自动清理。重启只清理能够确认归属且生产进程已退出的待验证文件，不将其直接升级成已验证缓存；身份异常的文件保留且不复用。

`layout-tracking.js` 使用当前 SQLite 连接的临时触发器记录历史弹幕及过滤标记修改，不增加持久表或逐条事件日志。`RenderPipeline.layout()` 保留最多两份布局及活动轨道检查点，正常新增只读取新行，延续同秒配额、轨道占用与进场间隔，输出新数组以保护旧计划。迟到/同时间提前排序、历史修改、删除、替换、过滤变化、外部连接写入、字体或几何变化均保守回到完整重建。异步计算中发生修改会拒绝发布检查点。滤除新消息也可能触发保守重建，尚未优化为仅重算受影响后缀。服务端已排序的字符串 ID 省去重复排序与整批对象复制，浏览器未排序调用保持原行为。

密集排版的水平冲突由 `shared/danmaku-collision.js` 计算：对共同显示期间的运动矩形求屏内交叠面积积分，覆盖边界短暂追尾；候选纵向位置兼顾整体遮挡时间及最严重的一对。每份布局复用固定的评分数组和 8 个断点的工作区，不为每一对弹幕建立临时对象。条数、字号、源时间、速度、结束时间和既有最大进场延迟不变；极端密度仍可能重叠。排版版本升为 9，使旧位置缓存不被误用；已有成片保留。

Canvas 文字图片缓存继续限制为 20 MiB。每帧先确定真正与画面相交的集合，保护其中已缓存的项，优先淘汰离开画面的图片；工作集超额时只让超出的部分不进入缓存，并复用一个临时 Canvas，避免整批反复淘汰和重新分配。临时 Canvas 不计入常驻缓存，不能将 20 MiB 解释为整个浏览器内存上限。透明度、速度和区域变化重算位置，只有字体、字号或缩放实际改变时才使相应图片/度量失效。减少不可见绘制不会删除弹幕或改变时间轴。详细边界和对照见 [DANMAKU-PERFORMANCE.md](DANMAKU-PERFORMANCE.md)。

当前完整布局的排序和对象复制仍有同步阶段。独立压力验证中，36 万条弹幕的一次布局重建出现约 0.5 秒事件循环延迟。因此首版在进入录中布局前使用有界数据库计数，超过 5 万条弹幕或 1 万个连麦布局记录就暂缓录中处理；不删除、过滤或降质，录后仍使用完整路径。此门槛是保守的开发保护，不是所有设备上的无感保证。

闲时预处理由一个调度入口持有当前素材，每轮只安排一块或同素材的两块，不并行启动多份素材。默认 `idleRenderOptions.mode='adaptive'` 保持原来的两线程编码参数和缓存签名；在至少 6 核、8 GiB 内存且可用内存及缓存/磁盘预算允许时，先测两个单块，再试一轮双块。按批次墙钟时间除以完成的素材秒数比较，只有单位素材处理耗时至少降低 10% 才继续双块；后续连续两轮收益不足退回串行。小于 10 秒的块、尾块、取消、失败以及显著排队的批次不作为吞吐样本。资源紧张时临时降为单块，磁盘空间仍由缓存模块在实际构建前独立预留。

macOS 的可用内存按系统 `memory_pressure -Q` 返回的空闲比例估算，固定命令最多每 30 秒执行一次，1.5 秒超时，失败时回到更保守的 `os.freemem()`；其他平台使用 `os.freemem()`。`legacy`、`single`、`parallel` 是开发基准用的构造选项，不是新增用户开关：`legacy` 保持单块两线程；`single` 固定单块较多线程；`parallel` 固定双块但仍受资源门槛和失败回退约束。线程配置在一个处理计划中固定，策略决策和计时不进入缓存签名。自动模式不会改变画质参数、分辨率、帧率或弹幕数量。

排队任务可立即取消，运行中的任务须等子进程及全部管道退出后才能释放槽位或清理文件。后台遇到录制或手动导出仍遵循既有让出机制；整批取消后等待所有工作收尾，已验证的成块保留，半成品清理。一块并发失败时先取消并等待同批任务，再以相同编码配置串行重试未完成的块。媒体进程连续 120 秒没有新的进度计数时停止，FFprobe 仍有独立的 15 秒期限；不能用总任务时长判定长视频卡死。导出记录的 `performance` 保存阶段等待、处理和成品保存耗时，诊断写入失败不改变业务结果。`Media.prepareNext()` 也返回该轮 `performance`，包含后台 `render`/`probe` 等阶段和策略原因；最近 8 份素材的诊断只保存在内存 `preparationMetrics`，不写入用户业务数据。退出时先取消后台并等待其收尾再关闭数据库，计时清理只操作内存。

弹幕时间窗按不可变布局建立区间索引，结果仍遵守原有条数、过滤与排除规则。预处理保留最多两份计划进度，复用块签名，但每轮继续检查来源身份并重新持有已完成块的读取租约；来源、样式或缓存变化会重新核对。并发编码退回串行时保留同一编码配置下已验证的块；更换编码器或签名不兼容时仍走原有完整回退，不能拼接不兼容视频。

音频保留整片 AAC 安全复制条件，不放宽首关键帧与选段起点的偏差。需要重编码时仍保留原有重采样、精确裁剪、补静音和 FLAC→AAC 192k 路径，双版本共用一份音轨。单段直接 AAC 的试验在部分素材上增加编码耗时，未作为默认优化保留。多段保持无损中间拼接后只编码一次 AAC，避免每段独立编码的延迟积累。本轮短媒体验证发现旧版 FLAC 拼接在部分短尾块后会拒绝下一段较大的块，静音源与有声源的默认位深也可能不同，却以成功状态结束并产生截短音频；多段中间 FLAC 现统一样本格式及 800 样本块（48 kHz 下恰好整除 30/60 fps 的帧对齐片段），包括缺音轨时的静音段，最终转换启用解码错误即失败。取消仍等待进程及来源读取租约释放，不发布部分音轨。

整场导出的时间线和复用判定由 `server/export-plan.js` 共用，最终成片统一经过 `Media.publishFiles()` 的保存清单、发布和失败恢复。完整且兼容的多来源录像可直接封装原始 H.264/AAC，按明确的片段时长去掉真实断流空缺；编码头历史变化、尺寸或参数不兼容以及连麦标注继续进入原有完整编码。合并前后核对帧数、时长、音轨数量和编码签名，失败则整份纯净结果以同一编码配置重建，不能混拼部分复制和部分重编码的画面。

来源首视频关键帧可能比片头 AAC 晚约 21 ms。完整来源复制另用 `sourceStream(...,{wholeSource:true})` 从已封口的第零片段保留所有片头音频，并验证首个视频包确为关键帧；已整理原片也从验证过的文件头读取。此通道只接纳不超过 100 ms 的启动偏移，不改动精确剪辑或已有独立音频复制的关键帧条件。双文件导出先复用有效弹幕块，再封装纯净视频并直接复用其中的 AAC 音轨，无需再次读取整场生成 FLAC/AAC。原画面封装失败保留已验证的弹幕视频；明确的 AAC 封装错误只修复音频。保存失败保留完成的 MP4，重试保存不重新编码。性能方法及适用范围见 [EXPORT-PERFORMANCE.md](EXPORT-PERFORMANCE.md)。

单独弹幕版的整场音轨由 `server/export-audio.js` 处理。完整、编码头兼容的 AAC-LC 来源先逐包验证采样率、声道、配置、连续时间戳和尾部时长，封装后再核对音轨、包数及起止时间；多来源还检查重连处前置静音和累计时长。通过后直接复制 AAC，避免再次有损编码。时间戳空缺、延迟、配置变化或封装不一致继续走精确补静音及 FLAC→AAC 修复。精确剪辑仍使用样本级裁剪，不以 AAC 包边界代替用户的切点。音频输入只向 FFmpeg 发送原有时间戳的音频包，按 64 KiB 聚合，避免把无用的视频包传入音频进程；来源读取租约和取消仍由原有通道管理。

精确弹幕剪辑通过 `server/cached-video-slice.js` 划分可复用区间。只有同一有效样式、字体、排版及来源指纹的缓存才会进入判定；逐包验证 H.264 恒定帧率、无 B 帧、PTS/DTS 一致及关键帧索引。从下一个关键帧到结束前关键帧之间、至少一秒的完整区间直接复制，首尾从原片按原质量参数逐帧重绘。复制后核对帧数、零起点、时长和编码签名；局部失败只重绘该区间，拼接签名不兼容仍使用原有完整回退。未准备、很短或无法验证的区间沿用原流程。缓存租约持有至成片完成，最多保存八份关键帧索引，每次探测最多 8 MiB / 15 秒；没有扩大画面缓存容量、编码并发或后台预算。任务诊断中的 `reusedVideoSeconds` / `renderedVideoSeconds` 记录实际复用和重绘时长，`audioCopyFallback` 记录音轨复制退回原因。

首次绘制的解码回读由 `server/render-sequence.js` 区分视频重排与弹幕存续时间。已有全局排版继续提供进入区间前尚未离场的弹幕；视频元数据含有效 B 帧重排信息时，只为视频重排和关键帧解码保留必要前滚。旧元数据缺少该信息时保留原有六秒回读。`renderVideo()` 与连续处理共用同一滤镜、ASS、头像、帧对齐和编码质量参数。

同一已封口来源的相邻区间可用一次解码/绘制/编码输出最多两块、合计不超过 120 秒。按累计帧数强制关键帧并分段，每块独立重置时间戳，逐块核对帧数、零起点、时长及编码签名。编码头发生变化、录中处理、动态连麦头像、过短区间或资源保护命中时使用原流程。连续处理失败退回对应区间的独立绘制。前台仍只读取已有缓存、使用导出临时目录，不因零缓存导出申请后台缓存额度。后台的两个缓存生产者先各自预留空间，登记齐后共用一个解码进程，仍各自完成来源验证和缓存发布；缓存命中、预留失败或取消会结束等待，不留悬挂进程。已提交块保留，未完成批次允许重新处理；没有让未完成的分段成为缓存命中。

硬件前台合批在本机实测有回退，故保留原有独立、最多两路的硬件前台分块；连续处理用于适合的后台及软件缓存路径。中间 MP4 无需为了网页渐进播放搬移文件头，最终成片统一在封装时做 `+faststart`。试验、撤回及实际零缓存测量见 [COLD-EXPORT-PERFORMANCE.md](COLD-EXPORT-PERFORMANCE.md)。

导出入队前，`BackgroundPreparation.yieldForExport()` 对比当前批次与导出快照的实际分块签名。素材已结束、来源封口、配置一致且请求完整覆盖当前批次时，导出通过内存消费者接用当前批次，入队即可返回，处理进度等待该批次验证完成。很短的选段不等待无关整块；大型 CPU 零缓存导出也不会因接手第一块而改走较低预算路径，只有原本已有有效缓存或当前批次能覆盖全部请求才接手。后台不再安排下一批，当前批次保留；后续绘制仍遵守全局并发限制。录制开始、样式/来源失效、用户暂停或关闭仍中断它。取消排队或运行中的导出会释放消费者，最后一个消费者离开时停止相应批次。入队失败、关闭和异常同样释放关系；这些内存关系不写入业务数据库，重启仍按已有缓存和导出恢复清单重建。该机制也允许已结束录制中尚在收尾、且签名一致的录中处理块完成验证。

导出恢复由 `ExportCheckpoints` 记录完成步骤。记录绑定任务快照、来源范围指纹、弹幕布局、字体/样式和编码配置；普通路径按来源片段，缓存路径按现有绘制单元，再分别保存音轨与最终封装。

已结束并封口的长素材，在没有可复用预处理结果的 CPU 导出中使用 `cpu-chunks-v1`：选段有效时长达到 60 秒后，按目标帧网格分为最多 60 秒的独立视频块，逐块编码、校验帧数/时间/编码签名、同步文件和原子保存记录。纯净版能够直接复用原片时继续复制；必须重编的纯净版也分块，保留原片帧率，并按音轨的累计输出时间分配帧数，避免多段独立取整造成漂移；需要补末帧时只重复所选区间内的画面。弹幕版沿用用户设置。保留常规 CPU 的 CRF 20、veryfast、B 帧和线程上限，每次只编码一块，不将它转成较低预算的后台缓存，也不与缓存块混合拼接。全局弹幕与连麦时钟不随分块重置。需要修复的音轨先按相同边界保存无损 FLAC，最后连续编码一次 AAC；原音轨可复制时不重编。最终只复制拼接视频与统一音轨，不再次编码视频。

崩溃恢复固定原来的 CPU 路径，即使之后出现缓存或可用 GPU；来源、样式或编码配置变化仍会使旧检查点失效。单块编码失败保留已完成块，不自动退回整段重做。旧版常规路径已有恢复工作区时保留原路线，以免升级丢弃大段已编码成果。通常只需补当前未完成的视频块，但音轨最终编码、整段快速复制和最终封装仍各有自己的完成点；不能把“60 秒素材”解释为固定的墙钟恢复时间。来源身份无法用于复用时，从原素材重新分块但不冒用旧进度；未封口的录中选段与短 CPU 选段继续沿用普通路径。验证和性能范围见 [CPU-EXPORT-CHECKPOINTS.md](CPU-EXPORT-CHECKPOINTS.md)。

每份任务的工作区使用现有所有权与进程登记保护；步骤记录以原子替换保存，另留上一份有效记录。复用前核对文件身份和 MP4 结构，损坏或缺失只使对应步骤重做。退出、崩溃和一般处理失败保留已完成步骤；用户主动取消或确认删除任务会清理该任务的处理工作区，原素材及独立预处理缓存保持原有管理。确认删除素材时可清理它的非活动处理检查点，待保存成片仍受保护。成功发布后清理工作区。已确认退出的所有权可安全移交；未知或仍活动的进程不被抢占。归属标记也先写入并同步新副本再原子替换，写入失败时保留旧标记。

开始处理媒体前将恢复意图写入任务；启动时会对有处理记录的意外中断任务安排恢复，同一任务自动恢复最多三次，超过后转为用户手动“继续导出”。`POST /api/jobs/:id/retry` 保留原任务的选段与配置，不接受客户端覆盖这些内容，并与取消、删除状态互斥。临时占用、文件描述符不足和明确的临时资源错误按 250/500 ms 退避，单次调用默认最多两次额外重试、单次导出总计最多六次；嵌套阶段共享总预算，上层阶段重试时仍会跳过已验证的完成块。每次重试创建新的输入流；取消会打断退避。磁盘满、权限问题、来源缺失/变化及未知错误不会盲目反复编码；需要用户处理时保留恢复入口与“查看暂存文件”。

成片准备发布前，在归属标记中保留原任务、目标及已验证文件身份。清单未创建或在 staging 阶段损坏时，可据此重新验证并重建，直接重试保存。发布可能已操作目标后，清单缺失/损坏不会自动猜测归属或清空旧凭据，保留现场并提示检查。目录冲突、空间不足及切换目录仍走既有不覆盖保存流程。正常恢复记录及分块不依赖网络；真实断电、硬盘损坏或操作系统未落实的写入仍不能保证恢复全部数据。

## 当前数据流程

弹幕默认每房间 50 条/秒，设置可调 1～50。抖音在写 XML 前执行配额和长消息过滤；B 站下载核心保持原样，工作台限制新增索引。共用规则过滤 30 字及以上消息，以及滚动 10 秒内达到 5 条的同文重复；列表、预览、密度和新导出保持一致。密度图还保留抽样前的汇总计数。限制与维护说明见 [DANMAKU.md](DANMAKU.md)。

纯数字房间号以字符串保存和解析，不将抖音长房间号转换成 Number。添加前并行只读查询 B 站及抖音：仅一个确认存在且另一平台确认不存在时直接添加；同号两边均存在时返回主播、平台及开播状态，界面选择后使用对应平台的完整链接添加。某个平台查询失败时要求确认已找到的主播，不能把超时当作不存在。查询和取消弹窗均不创建监控、录像或修改已有启停状态；完整直播链接保持直接识别。抖音响应明确返回主播身份但没有当前直播场次时可作为未开播房间监控，实际开播后再使用当时返回的直播场次 ID。

1. 录制核心写入内部 `data/originals` 的 FLV/XML；工作台建立小段和连续时间轴，支持录制中回看、选段和排除弹幕。

   抖音独立写入 `data/originals/douyin/<webRid>/`。会话 `room=0`，平台归属记录在 `douyin-session:<sessionId>`，删除素材时一并移除；公开房间键为 `douyin:<webRid>`，不会与 B 站数字房间号混淆。访客 Cookie、签名地址只驻留内存，不写入设置、快照或日志。房间列表只保存标识、名称与监控偏好。抖音工作线程异常只恢复弹幕连接，不重启视频。关闭服务先停止并收尾这些写入，再关闭数据库；下次启动恢复启用的房间监控。B 站文件扫描跳过该独立目录。

   抖音视频初始地址仍须属于平台 CDN；该地址返回的跳转链允许使用公网 IPv4/IPv6，逐跳检查协议、端口、凭据及特殊地址范围，最多请求六次。本机、内网、链路本地、组播和保留地址不会被访问，视频请求不携带访客 Cookie。原画选择、FLV 内容、画质及时间戳规范化流程保持一致。
2. 录制结束并整理完成后，自动登记弹幕预处理。没有自动纯净版导出，也没有额外纯净缓存。
3. 用户手动导出选段或整场，可选纯净版、弹幕版、双文件。满足条件的整场纯净版复制码流；弹幕版复用有效缓存，缺口现编，保持原分辨率、60 帧和现有质量参数。
4. 删除录像素材会清理内部原件、小段、预处理缓存和工作文件，保留已导出成片。删除导出任务是独立操作。连续 30 秒无进展时停止安排后续删除，保留剩余清单供重试。

旧归档的路径、引用和清理检查用于保护及删除本地已经存在的文件。它们不生成新归档，不能因为名称含有“旧”就当作无用代码移除。数据库恢复、文件身份校验、读取租约和保存失败重试同样属于当前数据保护。

## 预览时间戳与更新提醒

`RecordingTimestamp.vue` 是视频外的 DOM 文字叠层，日期和时间使用同一字号与样式。默认关闭，设置项为 `preview-timestamp`；复用 `recording-time.js` 的片段墙钟锚点，以实际播放器时间定位，按整秒更新。它不接入原始录像、预处理、绘制缓存或导出参数，切换开关不使视频缓存失效；关闭后卸载媒体事件监听与尺寸观察。

`UpdatePrompt.vue` 展示后台已验证的新版本，不依赖用户打开设置。启动时重新查询，之后每天检查，沿用主备更新源与签名/哈希校验；网络失败不弹出虚假的更新信息。普通关闭只在当前窗口内屏蔽同一版本；勾选后将发布身份保存到 `update-ignored-version`，新版本身份不会被旧偏好屏蔽。提醒不会覆盖正在编辑的其他弹窗，点击外部不关闭，支持关闭按钮、圆形叉号与键盘焦点约束。立即更新复用现有下载与空闲安装流程，不打断录制或导出。

## 开发与发布

先在当前 PowerShell 中点调用 `scripts/dev-env.ps1`，再恢复依赖、运行测试或构建。开发数据、工具缓存和发布验证目录位于源码仓库 `.tools`，不要对运行中的真实 `data` 创建 `Store` 来检查内容。

`npm run dev` 通过 `scripts/dev.js` 动态创建隔离服务及 Vite 代理；Vite 配置不再保留指向旧固定端口的备用代理。`npm run build` 清理并重新生成自身的 `dist`。

本机服务及新录制核心的自动地址分配会避开 [Fetch 标准禁止的端口](https://fetch.spec.whatwg.org/#port-blocking)，不发布浏览器无法访问的地址。

桌面关闭默认每次询问，可选择退出或后台运行；勾选“不再提示”后将所选动作保存在数据库设置 `window-close-action`。页面设置与桌面提示写入同一项，下一次关闭即生效。用户退出走已认证的 `quit` 操作：空闲及监控直接受理，录制或导出须确认。窗口受理后立即关闭，后台停止核心、预处理和编码，再等待文件及数据库操作收尾。安装维护的 `exit` 和版本切换的 `restart` 仍等待工作安全完成，不中断任务。

退出前将未完成导出持久化为 `interrupted`，在 job 数据中记录 `resumeOnLaunch`；恢复时保留范围、排除弹幕和导出模式，复用现有渲染缓存。已编码成片按发布清单继续保存，其他任务重新入队，完成后清除恢复标记。满场命名重新占用预约，避免覆盖已导出文件。用户主动取消的任务不恢复。退出时先停监控和录制并验证自有核心身份再停止进程，下次连接核心后恢复启用房间；关闭期间的直播内容无法补录。

B 站房间的启停意图和自动录制偏好分别保存在数据库设置 `bilibili-rooms`，与抖音的记录独立。用户点击停止先持久化，再关闭核心房间的自动录制并停止当前录制；退出时的临时停止不更改用户意图。核心的 `AutoRecordForThisSession` 会在重启或下播后复位，不能用于长期保存停止状态。启动自有核心前只针对已停止或关闭自动录制的房间关闭其配置中的 `AutoRecord`，防止连接 API 前抢先录制；核心仍负责原有下载流程。连接后按持久化状态恢复，旧退出名单不能覆盖明确的停止；操作按房间串行，轮询也会修正停止状态。房间名称和启停状态从本地快照立即显示，实际录制及直播状态仍由核心查询确认。只保存房间标识、名称、标题与布尔偏好，不保存直播地址或登录凭据。

正式发布按 [RELEASE.md](RELEASE.md) 的白名单取源码、程序和许可。运行包排除 `node_modules`、SDK、开发缓存、录像、数据库及用户配置；不要直接压缩整个开发目录。源码包保留测试、构建脚本和对应录制核心源码。
