# Cookie 管理（0.3.0）

设置 → 软件更新下方 → Cookie 管理 → 管理 Cookie。仅保留 B 站：未填写时点“去填写”，已保存时点“去更换”。每次打开输入框均为空，保存后清空输入；没有查看旧内容、显示密码或导出凭据入口。教程折叠展示，不主动提醒用户填写。抖音继续免登录录制，不提供账号 Cookie 管理；升级时只删除旧版的 `douyin.sealed`，不会读取或解密它。

## 获取 B 站 Cookie

1. 在自己的 Chrome 或 Edge 浏览器中登录 B 站。
2. 复制 `https://api.bilibili.com/x/web-interface/nav`，在同一浏览器打开；页面出现文字是正常的，不用复制正文。管理弹窗提供“复制网址”按钮。
3. 按 F12（Mac：⌘+⌥+i），进入“网络 / Network → 全部 / All”，刷新后点击 `nav`。
4. 在“标头 / Headers → 请求标头 / Request Headers”中复制 `Cookie` 右侧的整段值，粘贴并保存，无需手动拼接字段。

无需在控制台运行代码。Cookie 是登录凭据，不应分享。保存成功表示本机保存成功，不等于平台登录验证通过。

## 本机保存与替换

- macOS：钥匙串保存随机 AES-256 密钥；本机文件只保存 AES-GCM 认证密文。钥匙串项不参与同步，设置为解锁时、仅此设备可用。原生 helper 是随包构建和签名的组件，不在运行时下载或编译。后台读取不弹授权框；用户主动保存或点击“解锁已保存的 Cookie”时，若系统需要重新授权，允许 macOS 显示钥匙串授权提示。解锁复用原来的密钥与密文，不要求重新粘贴 Cookie，也不创建替代密钥。正式升级应沿用稳定的发布签名身份。
- Windows：使用系统 PowerShell 的 `ProtectedData` / 当前用户 DPAPI，保护数据绑定平台和数据目录上下文。打包脚本明确包含该保护脚本，不依赖用户自行安装模块。
- 独立目录 `<内部数据目录>/private-credentials/`，仅保留一个 `bilibili.sealed` 文件。Mac 默认位于 `~/Library/Application Support/Caibo/data/private-credentials/`；Windows 默认位于程序的 `程序组件/live-editor/data/private-credentials/`。不写进普通 JSON 配置、SQLite 或日志。目录及文件分别请求 0700 / 0600 权限。
- 新值先加密，再写入只有密文的临时文件，落盘成功后原子替换旧文件。加密或写入失败则保留旧保存项及旧运行值；成功后不保留旧版本备份。文件系统快照、用户备份或磁盘底层残留不属于应用可保证擦除的范围。
- 密钥或解密不可用、密文被修改、平台不匹配时，以匿名模式继续；不会自动覆盖原密文或降级为明文保存。正常版本更新沿用原数据目录、密文格式与系统密钥，不清空 B 站 Cookie，也不把版本号或新程序哈希加入加密上下文。Mac 若因助手签名变化而需要系统授权，可解锁原内容后继续使用。数据目录的绝对路径仍参与加密上下文；搬移数据目录或跨设备迁移不属于原位置覆盖更新，系统密钥丢失时也无法恢复。
- 接口只返回已保存、已加载和错误状态，没有读取原文的接口。原文仅在本机进程内存和到对应平台的请求中使用。原生 helper 通过标准输入输出传递数据，不经命令参数、环境变量或明文临时文件。
- 不自动读取浏览器账号，不上传到菜包网站；只把 B 站账号 Cookie 发到固定官方 API 和 B 站弹幕连接，API 禁止自动跳转。视频 CDN 不携带登录 Cookie。

这些措施主要防止普通配置泄漏和密文文件被复制后的直接读取。应用仍需在运行时使用明文；不能承诺抵御已控制当前系统用户的恶意程序或内存读取。

## 录制核心与生效范围

B 站核心新增受本机回环地址、随机 Basic 鉴权和 `BREC_EPHEMERAL_AUTH=1` 开关共同限制的内存接口，拒绝带 Origin 的浏览器直接请求。该模式下不读取传统配置 Cookie，不使用自定义 API 域名。旧核心缺少接口时会显示需使用配套新核心，不向传统明文配置回退。

新的 B 站 Cookie 会应用到后续平台查询，并重连弹幕认证，不主动中断视频写入。临时连接失败后会重试。B 站完整保留含连字符的 `buvid3`。抖音只使用平台匿名访客标识，日常访客刷新不强制断开健康的弹幕连接。

两平台的弹幕昵称验证目标不同：B 站需要验证有效 Cookie 是否让新收到的弹幕返回完整昵称；抖音在未填写账号 Cookie 时已经可以完整获取发送者昵称，Cookie 不是抖音完整昵称的前置条件。

有效的 B 站登录态还**可能**让平台开放更多画质档位，取决于账号权限、直播源和平台接口。程序继续选择可用的最高兼容 H.264/AAC 档位；更高画质在下一次连接视频流时使用，不进行插帧或超分辨率，也不能补回历史已匿名化的用户名。不能保证填写后所有 B 站昵称均恢复、获得原画或更高帧率。
