## 处理与恢复范围

- 新的 CPU 零缓存任务，在素材结束且封口、选段有效总长至少 60 秒时走 `cpu-chunks-v1`。视频块不超过 60 秒素材，按目标帧网格对齐，依次完成编码、文件校验、同步和原子保存记录。不会把两个块合并成一个恢复步骤。
- 复用统一导出流程：纯净版符合条件就复制原片；必须重编时也分块，保留原片帧率；弹幕版保留用户帧率、全局排版、字号、显示区域与连麦标注。仍用 CRF 20 / veryfast 和既有 CPU 线程上限，保留常规 B 帧。每次只编码一块，不增加同时编码的视频数量。
- 修复音轨时保存分块 FLAC，最后连续编码一次 AAC，再复制封装到成片。没有在每个视频块单独编码 AAC 后再相接；可复制的原音轨继续复制。
- 纯净版与音轨共享累计输出时间轴，按累计时长分配原帧率的视频帧数；不能逐段独立取整后累积误差。需要保持最后一帧时只从所选区间内读取，避免取到剪辑区间外的新画面。
- 已完成块核对身份和 MP4 结构后复用；损坏的块单独重做。单块失败不会再转回整段编码。原始素材、独立预处理缓存继续受现有保护。
- 恢复固定原路线。CPU 任务不会因新 GPU 或缓存出现而丢弃进度；旧常规任务已有工作区时继续原路线，以保留可能已经完成的大段输出。缓存只有实际匹配当前配置/选段才值得采用预处理配置。

通常一次中断只重做当前未完成的视频块，最多约 60 秒素材；这不等于最多等待 60 秒。最终 AAC 编码、直接复制和最终 MP4 封装仍各有独立完成点，来源身份或编码配置变化也会使复用失效。未封口的录中导出、短 CPU 选段和已有缓存任务继续采用各自原有路径，不将所有路径都宣称为一分钟恢复。

## 实际故障与画质验证

`test/cpu-export-checkpoints.test.js` 使用真实 FFmpeg / FFprobe，覆盖：

- 单个长来源在第二视频块编码时 SIGKILL；弹幕、双文件、纯净三种模式重启后均跳过第一块，只补第二块和尾块。恢复时模拟新增缓存及 GPU，仍保留 CPU 进度。
- ENOSPC、EIO 不盲目重试；EBUSY 有限重试后保留第一块，故障解除后继续。普通编码异常同样不会整段重编。
- 已完成块被改动时，只重做该块及尚未完成的尾块；取消会清理任务检查点并释放子进程和来源读取。
- 29.97 fps、无音轨、30/60 fps 单帧尾块、三小时的帧网格规划、升级前已有完整常规输出等边界。
- 多段精确剪辑的帧率不同步边界：4 段各约 15.017 秒，旧的逐段取整得到 1800 帧，音轨对应的正确 30 fps 总量为 1802 帧；新流程按累计时间轴分配帧数。另用 7200 段的规划验证误差不随段数累积。
- 约 130 秒动态素材的实际 CRF 20 分块输出与单段参照对照；另外用无损编码隔离压缩/GOP 差异，逐帧核对整段和分块的画面、弹幕位置。生产编码的 DTS 连续、PTS 不重复；最终视频可完整解码，帧数、分辨率、帧率和音轨时长核对，音频接缝附近仍有连续声音。

CRF 输出在新 GOP 附近不保证与整段编码逐像素相同。旧 CPU 路径与全局帧网格的取样相位也存在差异，不能把两者在同一小数时刻的抽帧 PSNR 直接当成同一源帧的画质变化。这里以质量参数、完整解码、时钟校验和独立无损分块对照判断正确性，不宣称成片无损或逐字节相同。

## 正常导出耗时

Apple M5 / 10 核 / 16 GiB，约 124.992 秒 1080p30 动态 FLV + AAC，3 条弹幕/秒，输出纯净版与 1080p60 弹幕版。全新独立资料库，无预处理。按“旧、新、新、旧”各两轮串行测试，计时包含入队、编码/复制、音轨、封装和发布到隔离本地目录；不含素材生成、索引、字体导入和成片验证。没有同时跑其他重负载测试。

| 项目 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 两轮耗时 | 67.054 / 70.240 秒 | 55.389 / 62.964 秒 |
| 平均 | 68.647 秒 | 59.177 秒 |

该样本平均减少 **13.80%**。新流程还避免了旧 CPU 路径对这份有 21 ms 起始偏移的素材重复编码纯净版和音轨，纯净版直接保留原画面与音轨数据。因此不能把全部收益归因于分块，也不能保证每种素材都快 14%。两轮结果有明显波动；需要重编纯净版的长精确剪辑仍可能增加解码/启动开销。

只按本机这份样本线性换算，双文件两小时素材约从 65.9 分钟到 56.8 分钟，少约 9.1 分钟；三小时约从 98.9 分钟到 85.2 分钟，少约 13.6 分钟。没有实际录制或导出两三个小时，这些不是跨设备承诺。恢复方面的主要收益更直接：保留此前所有有效块，不再因为最后一小段失败而重做整个长来源。

复现实测：使用 `scripts/benchmark-cpu-checkpoints.mjs --before <本轮修改前源码目录> --source <测试 FLV> --output <新的隔离目录> --seconds 125`；设置 `FFMPEG_PATH`、`FFPROBE_PATH`、`CAIBO_TEST_FONT`。原始四轮数据在 `benchmark/run-*.json`，汇总在 `benchmark/summary.json`，失败及修正过程日志也保留。Windows 实机、真实断电和损坏存储设备未验证。
