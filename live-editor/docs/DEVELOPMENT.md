# 菜播·录包机开发规范

本文面向维护者、开发者和参与修改代码的自动化工具，规定修改边界、兼容要求、测试证据与交付方式。用户使用说明仍由 README 承担；模块实现见 [ARCHITECTURE.md](ARCHITECTURE.md)，打包与正式发布见 [RELEASE.md](RELEASE.md)。

初次整理：2026-11-07。依据为当前本地开发源码，不代表这些改动已经发布。

**本文中的“必须”是开发和验收要求，不等于对应能力已经实现或验证。** 已有保护、历史问题和待补齐项分别记录。每次交付必须说明实际验证范围，不能用本文替代测试报告。

## 1. 最重要的原则

1. **优先保障录制连续性与已经录下的内容。** 界面、昵称解析、弹幕连接、诊断、预处理或更新失败，不应直接停止健康的视频写入；视频和弹幕分别恢复。磁盘写入失败、空间不足等无法继续安全保存的情况，保留已写内容并明确报告。
2. **新版本必须继续使用可读取的旧素材。** 播放、定位、剪辑、弹幕排除和导出不能要求用户重新录制；也不能因为新增平台字段或优化缓存缺失而默认素材损坏。
3. **人看到的必须与实际状态一致。** 已保存 Cookie 不代表登录有效；服务就绪不代表正在录制；连接成功不代表收到或写入消息；画面上的时间和选段实际位置必须对应。
4. **原始数据与派生结果分开。** 原片、原始弹幕、剪辑决定、用户设置和有效成片需要保留；缓存是否可重建必须有依据，不能按目录名称猜测。
5. **纯重构保持行为与兼容性。** 整理文件、拆模块、提取主题和文案不能附带改变录制算法、接口、存储格式或默认值。确需变化时单独说明、验证和记录。
6. **只完成授权范围。** 本地修改、运行测试、更新独立测试版、提交源码、正式发布和网站部署是不同的动作，按当轮明确范围执行。

## 2. 修改前的工作方式

- 确认真实源码目录、当前分支、提交及未提交改动；安装目录中的 `程序组件/live-editor` 是运行产物，不作为另一套源码维护。
- 阅读相关模块和已有测试，再定位修改点。先确定问题发生在输入识别、平台查询、采集、存储、索引、预览、导出还是状态呈现。
- 保留已有未提交工作。不要擅自 reset、clean、stash、覆盖整份目录、批量格式化或删除来源不明的文件。
- 修改前写清触发条件、原行为、预期行为、涉及平台与操作系统、是否影响旧数据。不能把推测的根因写成已确认结论。
- 独立开发使用 `npm run dev` / `npm run dev:server`。默认数据根为仓库下 `.tools/development-app`，端口为 17960 / 17961 / 17962；自定义 `DEV_PROJECT_ROOT` 也必须与正式数据隔离。不要把 `npm start` 当作隔离开发入口。
- 不接管正在运行的正式录制进程，不使用正式数据库进行破坏性测试。需要重启用户当前使用的实例时，先确认授权和运行任务；已有明确重启授权无需反复询问。
- 交付前检查 diff，确认没有混入本机配置、真实 Cookie、数据库、媒体、截图、日志、构建包或无关改动。

## 3. 架构与代码质量边界

| 责任 | 当前入口 | 修改规则 |
| --- | --- | --- |
| 服务装配与生命周期 | `server/index.js`、`app-lifecycle.js` | 装配依赖与关闭顺序，不继续塞入平台协议、媒体算法或大段路由业务 |
| HTTP 接口 | `system-routes.js`、`settings-routes.js`、`material-routes.js`、`http-response.js` | 保留认证、状态码、错误结构、取消和请求生命周期；前端不绕过统一 API 层 |
| 多平台协调 | `multi-platform-recorder.js`、`recorder-platform.js`、`bilibili-platform.js`、`douyin-platform.js`、`xiaohongshu-platform.js` | 共同操作由协调器分发，平台专用协议与状态留在适配器内部 |
| 状态事实与展示 | `app-activity.js`、`workbench-snapshot.js`、`src/state-sync.js` | UI 展示事实，不用文案反推业务状态；阻止旧请求覆盖新选择 |
| 界面编排 | `src/App.vue`、`src/use-*.js`、`src/components/` | 页面负责组合，播放器、打点、设置、导出等状态归各自模块管理 |
| 可见文案 | `shared/ui-copy.js` | 常规文案整理只改值，键名与函数参数保持稳定；新增文案应集中管理，接口错误码不充当可见文案 |
| 工作台主题 | `src/theme.css`、`src/style.css` | 色彩集中到现有主题变量，样式文件引用变量；Canvas 的主题色与工作台同源 |
| 媒体与存储 | `media*.js`、`render*.js`、`ingest.js`、`storage-files.js` | 不用界面重构顺便改排版、编码、读取校验和数据生命周期 |

规则补充：

- 当前源码相对路径均以 `live-editor/` 为基础，除非另有说明。平台图标、视频叠加样式、导出配色与工作台主题的作用域不同，不能把改主题自动扩展为改成片颜色。
- 只有语义相同、生命周期相同的重复代码才抽公共模块。B 站与抖音协议不同，不为消除一个 `if` 强行统一错误含义或重试方式。
- 异步工作必须有明确持有者、取消信号和收尾路径。监听器、定时器、Worker、子进程、文件句柄、读取租约与数据库连接必须释放。
- 后台当前按 `server/*.js` 收集运行模块。移动到子目录时同步核对构建标识、打包白名单和验证脚本，避免开发环境可用、安装包缺文件。
- 不把生成的 `dist`、旧 bundle 或安装包反向修改为源码；依赖升级与业务修复尽量分开，记录兼容原因与运行时要求。
- 不修改作者名「瞌睡小菜包」，不丢失第三方来源和许可声明。

## 4. 旧素材、旧设置与升级兼容

### 4.1 旧素材是发布验收的必测对象

不能只在空数据库中录一段新视频就宣布升级通过。涉及存储、预览、路径、安全权限、索引、预处理或导出的修改，必须用旧形态数据验证：

| 对象 | 最低检查 |
| --- | --- |
| 已完成旧录像 | 能打开、开始播放、中间定位、末尾定位；音视频可解码 |
| 内部片段模式 `chunks` | 封口片段、关键帧与历史编码头仍可读，不依赖重新下载 |
| 原片直读模式 `direct` | 整理后的索引能定位到原片，不要求已被合法释放的重复片段重新出现 |
| 旧剪辑与消息数据 | 起止点、排除、凸显、文字编辑、礼物/SC、已保存设置不被初始化覆盖 |
| 旧导出与缓存 | 有效成片保留；不兼容缓存明确失效并走可验证的重建路径 |
| 重启与升级 | 使用同一份测试数据重新启动后仍能预览和导出；原片、XML 和编辑记录保持一致 |
| 路径差异 | 中文、空格、Windows 路径/权限、macOS 路径与用户自定义存储位置 |

旧字段缺失、历史默认值和格式变化需要显式兼容分支，不能直接套用新建数据的必填校验。不能静默清空原数据后以“启动正常”作为成功依据。

### 4.2 正确认识 `PREP_SOURCE_STALE`

历史反馈：0.3.8 录制的 Windows 素材在升级 0.3.9 后出现“内部片段在封口后发生变化”，无法预览；0.4.0 的更新说明包含对此类历史素材问题的修复。

当前代码针对其中一种原因保留了兼容处理：Windows 权限传播等操作可能仅改变 `ctime`，视频内容未变。`source-range-identity.js` 先检查文件身份、长度和修改时间的差异，再进行内容摘要、关键帧及编码头复核。**不能据此认定所有同名错误都只是权限问题。**

修改这一链路时必须同时验证：

- 只有属性变化、内容一致：允许经复核继续读取，范围身份保持稳定，不改写原片和历史内容凭据。
- 内容被修改、替换、截断，或读取过程中发生变化：拒绝把旧索引/缓存当作有效结果，不忽略错误继续拼接。
- 优化索引无法证明有效，但仍有可安全读取的原素材：可放弃缓存或断点复用，进入既有正常处理路径；不能通过关闭来源校验“恢复播放”。
- 读者取消、失败与重新定位后：句柄和读取租约释放，Windows 下也可正常关闭或移动文件。

回归依据：[source-metadata-compatibility.test.js](../test/source-metadata-compatibility.test.js)、[material-preview-compatibility.test.js](../test/material-preview-compatibility.test.js)、[source-range-identity.test.js](../test/source-range-identity.test.js)。

### 4.3 缺少真实历史样本时

可以先推进平台拆分等与数据迁移无关的工作。用合成音视频、历史表结构、旧字段缺失和实际错误条件建立可重复夹具；有旧源码/旧安装包时，进一步由旧版本生成测试数据再交给新版本打开。

报告必须区分“模拟旧形态通过”“实际旧版本生成数据通过”“用户历史素材通过”。缺少真实样本时记录缺口，不要求用户提供 Cookie 或整份私有数据，也不把模拟测试写成所有存量数据已兼容。

### 4.4 平台身份与未知来源

- 新录制由实际平台接入链路记录来源，保持录像、弹幕、礼物和跟录记录之间的身份关系。
- 旧素材若无法可靠确认来源，应以“未知来源”兼容读取；不能因没有平台字段就拒绝播放、剪辑或导出。
- 不用主播昵称、数字房间号、文件名或缺失字段猜平台；平台不明时不能向任意平台接口发送该素材的身份信息。
- 未知来源是数据兼容策略，不代表该素材受损，也不授权自动回填猜测结果。统一来源字段、展示入口与历史迁移须单独实现和验收。

### 4.5 数据和设置迁移

迁移前在独立副本验证，实际用户数据迁移前建立可恢复备份，运行中的 SQLite 备份必须覆盖一致的事务状态。迁移应可重复执行，说明中断恢复方式、不可逆部分和老程序是否仍能打开；程序包回滚不等于数据库降级已经安全。

数据库或索引异常时保留原数据库、WAL 和原片，按既有恢复路径隔离损坏索引或异常记录；权限、空间和路径错误不能当作数据库损坏而自动清空。参考 [data-recovery.test.js](../test/data-recovery.test.js)。

新默认值只用于未配置项。已明确保存的用户值应保留；“曾采用默认值”与“用户主动保存了同一个数值”不能混为一谈。不得因为字段为空或新平台上线就覆盖既有录制开关、导出路径、样式或容量提醒。

## 5. 录制连续性、故障隔离与恢复

- 分别管理视频写入、弹幕采集、索引、预览、手动导出、后台预处理和诊断。一个子任务失败只影响必要的范围。
- 判断录制健康要观察实际写入字节、媒体时间/画面时间推进及写盘延迟，不能只看进程存活或 TCP 有流量。
- 断流、时间戳重置、分辨率/编码头变化应保留前一段，正确封口并在需要时新建来源，恢复后保持可解释的时间线；不能把参数不兼容的流直接拼成一份“成功”文件。
- 用户手动停止/移除后，迟到的网络响应、旧轮询和自动恢复不能重新开录。停止单个跟随目标时，不能误停其他目标或手动任务共享的录像。
- 未知状态不能当作下播；一次超时不能当作确认退出连线。保持现有确认、退避、失联保护与停止意图，修改阈值必须解释依据。
- 取消、退出或切换来源时，等待写入、子进程和持有的资源完成收尾。下次启动从持久状态恢复，不仅凭上次内存快照宣布“正在录制”。
- 普通后台预处理让位于录制；录中提前处理只在已有安全准入与预算内运行。状态不明、资源不足或录制受影响时退让后台，不降低或丢弃录制内容来保住优化任务。

参考：[RECORDING-RECOVERY.md](RECORDING-RECOVERY.md)、[LIVE-PREPARATION-VALIDATION.md](LIVE-PREPARATION-VALIDATION.md)。

## 6. 平台接入与外部接口变化

### 6.1 统一能力与平台差异

新增平台先在适配器中定义链接识别、身份核验、开播/连线查询、录像来源、弹幕与礼物、凭据应用、停止和关闭能力。明确支持、暂不支持和状态未知的能力，不把未实现接口返回空成功。

B 站、抖音、小红书分别验证。小红书当前本地接入公开 H5 视频、Cookie 后台网页会话、RWP 弹幕及稳定 UID 新场次监控，真实账号弹幕和连续跨场次仍待验收，见 [PLATFORMS.md](PLATFORMS.md)。平台适配器存在不等于全部能力已验收。

### 6.2 输入、身份与名单核验

- 支持范围内的整段分享文字应可提取链接，跟随短链时逐跳校验协议、域名和重定向；不读取推荐直播间来替代用户给定目标。
- 用户 ID、房间 ID、连线 ID 保持精确字符串，不能经过会丢失精度的 JavaScript `Number` 转换；昵称和列表位置不能代替稳定 ID。
- 查询结果必须属于请求的用户；直播间状态、所属主播和本次直播场次需要一致。冲突、多义或缺少证据应返回待确认。
- 房间号同时可能存在于不同平台时，保留已有消歧过程；一个平台暂时查询失败不代表它一定没有该房间。
- 连线跟录至少区分：本人开播、目标在其他房间连线、目标退出、暂时无法确认、目标切换房间。名单缺失不直接等同于下播。

### 6.3 抖音新版连线名单案例

0.4.1 的既有观众连麦名单查询使用 `linkmic_audience/list/v2`。在已实测的一种新视频连线场景，旧接口返回 `31001 / linkmic has closed`，但网页使用的 `list/v3` 能给出在席用户。

当前本地修复在这一个明确返回条件下补查 v3：核对房主 ID、当前房间 ID、在席状态，再按目标 UID 确认。保留旧接口成功路径；不把鉴权错误、HTTP 限流、网络超时或任意失败全部变成一连串接口重试，也不去掉名单核验来“提高成功率”。

接口版本、直播场景编号、SEI 布局版本是不同概念，不得互相代替。未知连线布局不猜画面坐标或人物归属。相关测试：[douyin-linkmic-roster.test.js](../test/douyin-linkmic-roster.test.js)、[douyin-user-discovery.test.js](../test/douyin-user-discovery.test.js)、[douyin-user-follow.test.js](../test/douyin-user-follow.test.js)、[linkmic.test.js](../test/linkmic.test.js)。

### 6.4 平台故障的验证要求

诊断沿“分享解析 → 用户核验 → 开播/连线状态 → 房间定位 → 名单确认 → 拉流 → 写入 → 播放/解码”记录在哪一层失败；HTTP 200 仍须检查业务状态码和响应结构。

保留脱敏、最小化、可长期运行的协议夹具，覆盖新旧响应、空名单、错误 ID、场次变化、接口不支持和异常输入。真实直播短测需有时长/大小边界并及时停止；用户正在使用的录制实例不作为自动化测试夹具。

成功的单场短测只能证明该时刻、该模式有效。平台兼容发布还应补充长时间运行、上下麦、房间切换、断网恢复及 Windows/macOS 实机，不能保证外部平台以后不再变化。

## 7. Cookie、匿名采集与网络问题

### 7.1 状态和错误必须分清

| 事实/错误 | 允许的解释与处理 |
| --- | --- |
| Cookie 已保存、可解密 | 只说明本地有凭据，不说明远端仍认可登录 |
| 明确的登录/认证失效 | 更新凭据状态；在平台允许且经验证的情况下匿名接续，优先保留视频与可采集消息 |
| DNS、连接超时、TLS、临时断网 | 网络异常，有限重试与退避，不宣告 Cookie 失效 |
| 限流或风控 | 独立报告、退避；不能以频繁切换 Cookie/匿名请求扩大重试量 |
| 成功响应但缺字段、协议变更 | 状态待确认/解析异常，不能当成空房、未开播或成功采集 |
| 消息收到但写盘失败 | 存储故障，连接状态和写入状态分别报告 |
| 正常停录、尚未启动连接 | 中性待机，不使用危险色制造连接故障 |

### 7.2 凭据生命周期应有的行为

- 用户保存、替换或移除 Cookie 后，后续请求使用当前凭据；在途旧请求不能把旧 Cookie 写回或用于新的连接。
- 录制中移除或确认失效时，视频写入独立维持；弹幕尝试受控匿名重连。匿名可能缺完整 ID、昵称或部分礼物能力，应如实反映，不因缺 ID 丢掉仍可用的弹幕正文。
- 匿名采集本身也可能被平台限制。不能保证所有平台、所有模式匿名可用；失败时保留已采集内容，说明具体失败环节并按策略重试。
- 已填入的凭据明确失效时，提醒应提供“前往对应平台 Cookie 设置”和“我已知晓”。确认后按该平台的本次凭据版本抑制重复弹窗；重新保存凭据后才开始下一轮提醒资格。
- “提醒已确认”只影响弹窗，不停止后台恢复、不抹掉错误状态。用户主动移除 Cookie 应按移除处理，不循环提示“请重新登录”。
- 凭据版本使用本地代次或合适的内部标识，不将 Cookie 明文写入通知去重键、日志或界面。

**现行流程：** 后台启动及低频轮询时，用各平台的本人状态接口检查已加载的 Cookie。同一份凭据的自动检查间隔至少两分钟，每次最多八秒。只有接口明确返回未登录才停用这份凭据，并通过热更新让弹幕接续匿名连接。凭据仍加密保留，提醒确认按保存版本跨重启生效。回归入口为 [platform-cookie-validation.test.js](../test/platform-cookie-validation.test.js) 和 [douyin-recorder.test.js](../test/douyin-recorder.test.js)。

### 7.3 网络诊断不能抢占录制

优先利用当前请求和 WebSocket 的连接、认证、关闭状态、首帧、首条消息、首次写入等被动事件。若新增主动网络检测，应低频、有超时和并发上限、可取消，不测速下载大文件、不在主写入循环阻塞、不使用检测失败直接停止所有任务。

诊断结果只表示所检测链路；同一个 Wi-Fi 不代表两台设备的 DNS、代理、证书、Cookie 和平台响应完全相同。当前被动诊断不能写成已经存在独立的全网检测器。

参考：[COOKIES.md](COOKIES.md)、`server/platform-credentials.js`、`server/douyin-chat-status.js`、`server/douyin-recorder.js`。

## 8. 预览、剪辑、时间与界面交互

- 区分媒体时间、北京时间、帧位置和真实断流空档。内部保留帧精度；格式化用于显示，不能把四舍五入后的整秒反写为切点。
- 逐帧操作后，相邻帧在播放时间、已打点的起止时间和短选段时长上应可区分。录制日期输入保持已有整秒交互；列表、更新检查和日志使用约定的北京时间，不随电脑时区漂移。
- 空输入不能偷偷回落为 0 秒或 10 秒并创建用户没选的范围。打点、输入、清空、切换素材分别验收；按钮禁用状态应与真实可执行条件一致。
- “回到最新”指已经录到且可以安全定位的最新位置，不指未来时间，也不固定落后若干秒。
- 拖动时间轴/定位器期间可更新预览定位和消息跟随；限制请求频率、取消旧请求，防止松手后迟到结果把画面拉回旧位置。
- 切换素材、关闭预览、暂停、重开和窗口缩放后，播放器、弹幕覆盖层、右侧列表仍对应同一份素材和位置。
- 弹窗外部点击须识别手势来源。在弹窗内按下滑条、拖到外部再释放，不能判为外部点击并丢弃未保存调整。检查嵌套弹窗、键盘焦点和 Esc 的作用层级。
- 服务状态、消息菜单等点击打开/外部关闭/键盘关闭行为不得因纯样式改动而改变。窄窗口、Windows 缩放和 macOS 滚动条下检查横向溢出、遮挡与按钮可达性。
- 空状态不伪装成故障；禁用、待机、进行中、失败各有明确含义。颜色与文字都表达状态，不只依靠一条难辨认的边线。
- GB/GiB、倍率/档位、帧率/速度等显示单位须与实际保存和执行值一致。默认缓存提醒为十进制 50 GB 时，不能实际等到 50 GiB 才触发；已保存旧值按兼容规则保留，单位转换不能造成每次保存都累积漂移。

参考：`src/video-time.js`、`src/recording-time.js`、`src/use-clip-markers.js`、`src/use-preview.js`、`src/backdrop-click.js`、`server/preparation-cache-warning.js`。

## 9. 弹幕、礼物、SC、搜索与排除

- 一种消息类型要分别核对接收、解析、去重、落盘、重开索引、列表、搜索、画面预览和导出。接收到协议事件不等于每一层都支持。
- SC（醒目留言）必须保留付费事件身份、发送人、金额及留言正文；不把它当空礼物丢弃，也不只保留礼物名而漏掉文本。
- 身份与正文分开存放和展示，避免“发送人”在上方昵称和礼物正文重复出现。不能为消除重复昵称误删真实留言内容。
- 当前交互中，无搜索词时“弹幕/礼物”切换决定列表类型；有搜索词时按全类型检索，关键词可以匹配正文、发送人及醒目留言等类型信息，按稳定时间顺序呈现。
- 右侧列表的类型筛选、搜索、跟随播放，与画面上的弹幕/礼物显示开关是不同状态，不能隐式改变导出或排除规则。
- 列表中的播放/凸显边框以画面实际显示区间为依据，不只用“最近一条”或固定一秒计时。暂停、跳转、排除、速度变化和密集弹幕都需验证，离场后恢复常态。
- 普通礼物、SC 和凸显弹幕的展示规则分别定义。预览有某种样式不自动意味着导出具有同样效果；未支持的导出路径需明确列出，不能悄悄消失却报告完全一致。
- 修改描边、光效、缓存图片时，大字直接绘制与 sprite 绘制效果一致；不附带改碰撞、轨道、消息数量、出现时刻或排除决定。
- 高密度验证同时观察画面、列表跟随、搜索和主线程响应；不能只用几条演示弹幕就声称大量消息也流畅。采集前按已约定的过滤/逐房间采样策略处理时，保留密度或省略信息；不得删除已经落盘的原始记录，纯样式或性能重构也不扩大采样丢弃规则。

参考：[DANMAKU.md](DANMAKU.md)、[DANMAKU-PERFORMANCE.md](DANMAKU-PERFORMANCE.md)、`shared/gifts.js`、`src/use-message-browser.js`。

## 10. 预处理、缓存、导出与删除

### 10.1 缓存是优化，不是唯一可读来源

缓存有效性至少涉及来源范围、编码头、时间、样式、字体、排版、消息编辑/排除和连麦资料。签名不兼容时重算；不得仅为提速关闭校验或把不同版本片段拼接为成功成片。

预处理失败应保留正常预览与可行的原素材导出路径。能安全读取原素材时允许放弃优化复用，但不能将真实内容变化吞掉。清理预处理缓存不能删原片、不可重建的内部片段或有效导出；缓存占用提醒不能擅自变为停止录制、自动删素材或限制预处理的硬阈值。

后台任务受统一媒体调度器、并发和磁盘预算管理；排队取消、运行取消和退出均需等待任务与管道结束。仅以进程存在或耗时很长来判断卡死都不充分，应观察实际进度。

### 10.2 导出的成功标准

- 实际生成可解码文件，并核对选段范围、时长、帧数/画面、音轨、断流拼接以及所选消息处理规则；不能只看 FFmpeg 返回 0 或 MP4 文件存在。
- 不兼容编码、帧率/尺寸变化、缺音轨和音频时间戳异常采用已有可验证回退；不以省时为由混用不兼容片段。
- 保存失败与编码失败分开。已完成的成片尽量保留并重试保存，不要求无条件重新编码。
- 完成文件可靠保存后才报告成功；取消或崩溃不能把半成品当最终输出，也不能覆盖用户已有同名文件。
- 用户删除导出任务、删除生成文件和删除源素材语义不同，确认文案与实际删除范围一致。

### 10.3 删除、搬移和空间整理

清理前确认路径归属、文件身份、共享引用和活动读取者；覆盖 Windows 大小写、目录联接、符号链接、中文空格和跨盘移动。取消、超时、异常退出后的未完成删除应可识别并安全重试。

不要把 `chunks`、原始 XML 或用户自选导出目录统称为“垃圾缓存”。卸载、升级、测试清理各自遵循明确范围，自动测试只操作自己的临时目录。

参考：[EXPORT-PERFORMANCE.md](EXPORT-PERFORMANCE.md)、[CPU-EXPORT-CHECKPOINTS.md](CPU-EXPORT-CHECKPOINTS.md)、`server/deletion.js`、`server/export-publication.js`。

## 11. 接口、诊断和安全基础

- Cookie 只通过系统安全保护和受控内存管理，不经命令行参数、环境变量、明文临时文件或普通设置持久化。安全保存失败保留旧值；升级保持凭据命名空间与数据归属，各平台凭据相互隔离。
- 本地服务的环回绑定、认证、实例隔离及来源校验不能因开发便利被跳过。测试使用已有认证辅助，不在生产接口添加“测试免认证”。
- 外部 URL、短链、CDN 重定向和头像下载有各自边界；重定向每一跳都需校验，不向媒体/头像地址发送登录 Cookie。
- 网络响应、协议解码、文件读取、WebSocket/Worker 队列和日志必须有大小、时间或数量上限。重试有退避、预算和取消机制。
- 诊断至少能关联操作、平台、失败阶段、HTTP/业务状态、WebSocket 关闭状态、重试和实际写入结果。敏感信息脱敏，不能输出 Cookie、访问令牌、带签名的完整媒体地址或用户私有路径全量内容。
- UI 使用短、可理解的错误，诊断保留定位所需的原因；不得把解析失败、认证失败、服务未启动全部压成无法区分的“网络错误”。
- 避免无条件打印每条弹幕。日志写入失败不应成为停止录像的前置条件；诊断包不默认包含整份数据库或录制内容。
- 对性能改动给出输入规模、设备、并发、冷/热缓存、CPU/内存/写盘与事件循环延迟。局部性能收益不能宣传为整场导出普遍加速同一倍数。

### 12.2 本地命令与环境

macOS 在仓库根目录准备现有运行工具后执行：

```sh
source live-editor/scripts/dev-env.sh
node --version
cd live-editor
npm ci
npm run test:dev
npm run lint
npm test
npm run build
```

运行工具来源、版本和校验以 `scripts/release-runtime.json` 及 [RELEASE.md](RELEASE.md)、[MACOS.md](MACOS.md) 为准。`dev-env.sh` 设置 Node、FFmpeg/FFprobe、录制核心与规范的临时目录，但不代替工具下载或构建。缺工具时先准备，不能以跳过媒体测试代替通过。

定向排查可先执行相应测试，例如在 `live-editor/` 下：

```sh
node --test test/source-metadata-compatibility.test.js test/material-preview-compatibility.test.js
node --test test/douyin-linkmic-roster.test.js test/douyin-user-discovery.test.js test/douyin-user-follow.test.js
```

Windows 使用已准备的 Node、FFmpeg、FFprobe、录制核心和相应环境变量运行共用测试，并执行既有 Windows 构建/安装验证流程。不要在 Windows 直接照抄 macOS 的 shell 环境脚本。

当前 `npm run lint` 只检查配置中的模块范围，不能称为全仓库静态审计。Node 测试、.NET 核心测试、原生桌面壳测试和浏览器交互测试也分别记录。

### 12.3 避免环境造成假失败或假通过

- 临时目录应独立、规范化并处于 `live-editor` 包作用域之外；macOS `/var` 与 `/private/var` 的符号链接可能触发路径保护，不能通过关闭生产路径校验解决测试环境问题。
- 使用正确的 FFmpeg/FFprobe 与字体。`ENOENT`、缺字体、端口被限制等说明测试未正常执行，补齐环境后重跑相关范围。
- 不能为了让测试变绿就修改安全约束、删除断言或把故障统一标为跳过。确需平台条件跳过时记录名称、数量及对应补测环境。
- `source-metadata-compatibility.test.js` 的 Windows 原生目录权限测试在 macOS 会跳过；`platform-credentials.test.js` 的 Windows 原生保护测试也有平台条件。macOS 总体通过不能算这些 Windows 专项已验收。
- 测试失败要说明是本次回归、原有问题、环境问题还是尚未定位；修复后运行相关范围。测试通过后，没有新改动或疑点不反复堆叠无关测试。

### 12.4 验证级别必须分开写

1. **静态检查/构建**：能解析、编译或打包，不代表业务可用。
2. **合成单元/集成测试**：指定输入和故障可复现，不代表第三方线上协议永远有效。
3. **本地真实短测**：本次身份、连线、媒体写入和解码有效，不代表数小时运行已验证。
4. **Windows/macOS 实机与升级验收**：分别列系统、安装包、旧版本、数据来源和结果；CI 软件编码通过不等于用户显卡/WebView2/休眠恢复通过。
5. **正式下载与更新渠道验收**：仅在发布范围获授权后执行，不能拿本地包代替线上更新结果。

按实际执行内容命名验收结果。例如当前 `scripts/verify-local-upgrade.mjs` 检查受控 UI 绑定/启停和 API 鉴权，没有载入旧版素材或执行真实升级器；不能仅凭脚本名称将它称为完整升级兼容验收。

## 13. 版本、打包、更新与网站

- 产品版本以 `live-editor/package.json` 为来源；相关锁文件、构建记录和清单保持一致。录制核心和网站有独立版本，不通过全仓字符串替换统一。
- Windows 与 Mac 正式包来自同一提交，记录版本、源码提交、工具版本和真实检查结果。禁止手工把未运行的检查填成通过。
- 采用白名单打包，排除真实数据、Cookie、密钥、日志、数据库、开发依赖、旧前端资源和测试媒体，保留对应源码与依赖许可。不要直接压缩开发目录公开。
- 修改运行模块、依赖路径、媒体能力或桌面桥接后，验证打包产物本身。源码测试成功不代表安装包带齐运行组件。
- 安装升级验证包含旧实例有序退出、任务空闲条件、数据保留、失败恢复、重开及旧素材可用。更新不能通过卸载清理用户数据来规避迁移问题。
- 按 [RELEASE.md](RELEASE.md) 核对两端产物、哈希、源码提交及签名清单，全部附件就绪后再公开稳定入口；避免用户拿到混合版本。
- 更新清单签名失败与网络失败处理不同，不能因为签名错误就绕过验证。哈希校验、系统代码签名和公证也不能相互替代。
- 网站下载页、更新说明和稳定更新入口对应同一公开版本；网站部署与桌面发布各自验证。发布后从实际公开地址检查文件、版本、大小和哈希。
- 更新日志面向用户，简短说明与上一版本相比的变化。临近版本需要带上用户可能错过的重要说明时保留必要上下文，不罗列内部函数；未验收或未发布能力不能写成已解决。
- 源码提交、草稿包、本地测试包不自动授权正式发布、签名渠道更新或网站部署。

## 15. 初次整理时仍需补齐或单独验收的事项

以下事项不得因为已有规划、适配器或测试文件就标为完成：

- **Cookie 实机验收**：自动失效检测、匿名接续与提醒有受控回归。仍需用真实登录态在 Windows/macOS 上录制中退出账号，验证 B站、抖音的实际匿名采集能力和接续情况。小红书的真实 RWP 消息与跨场次监控另需有效登录态验收。
- **历史素材统一来源**：未知来源是兼容约束；统一字段、旧数据识别/展示及迁移须在真实实现后验收。阶段性平台拆分不等于历史迁移完成。
- **用户实际旧库覆盖**：合成旧形态测试有价值，但缺少的真实历史版本、Windows 数据及迁移链条应保留为缺口。
- **新版抖音连线长期实测**：本地已对一场 v3 名单场景完成短时跟录，仍需 Windows 实机、长时间运行、反复上下麦及跨房间切换验证；不扩大结论到所有模式。
- **SC/礼物跨路径一致性**：当前有 SC 的索引、搜索和预览，导出路径有独立支持边界；必须逐项说明，不以预览存在来宣称导出一致。
- **独立主动网络检测**：已有被动诊断事件；完整主动检测如需实现，需按第 7 节验证资源预算和对录制的影响。
- **平台接入验收**：小红书已有本地视频、Cookie、RWP 和主页监控实现，真实账号与长期跨场次仍待验收。新增平台继续按协议、身份、采集和停止边界分别验证。

落实后更新本节，附实现位置、测试证据与仍未覆盖的场景；不要只删除“待验证”文字。
