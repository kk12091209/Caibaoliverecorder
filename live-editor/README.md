# 菜播·录包机：开发与功能说明

普通用户请先阅读[项目首页](../README.md)并下载 Release 运行包。

这是基于官方 BililiveRecorder v2.20.0 的本地剪辑工作台。官方 CLI 独立负责自动录制和弹幕采集；新增服务负责录制中的一秒内部素材、连续预览、非破坏性剪辑和导出；正常录完并校验后改为直接读取原片，自动释放重复分片。Windows EXE 使用 WebView2 显示本地界面，视频仍由录制核心直接下载保存，不是录制浏览器画面，不需要上传视频。

## 启动

下载 Release 中的 ZIP 并完整解压，或使用 7z / 自解压包，再打开里面的 `录播机.exe`。解压后的顶层只有 `录播机.exe`、`使用说明.txt`、`程序组件`、`导出视频默认路径`。应用、后台运行时、桌面配置和许可证统一保存在 `程序组件` 内，请保留整个文件夹。默认完整录像和剪辑导出分别保存到 `导出视频默认路径/完整素材`、`导出视频默认路径/导出片段`。普通用户不需要下载单独提供的源码 ZIP。桌面界面使用系统 .NET Framework 4.7.2+ 和 Microsoft WebView2 Runtime；录制核心、Node 和 FFmpeg 随包提供、独立运行。

也可访问已启动的 http://127.0.0.1:17860 。关闭窗口后后台仍会录制。在左侧点击房间的“停止”可结束本次录制；取消“自动录制”可取消后续开播监控。电脑关机/退出登录会停止服务；尚未安装 Windows 开机自启服务。 录制核心异常退出时，后台会自动重试并重新启动，已有监控房间继续保留；连接中断期间可以先填写直播间链接，恢复后自动启用添加按钮。鉴权失败或核心进程仍在运行时不会重复启动另一份录制核心。

发布包自带 Node.js、FFmpeg/FFprobe 和官方录制核心，不需要用户另装开发工具。开发时安装 Node.js 24+，运行 `npm ci`、`npm run dev`，使用下方说明的独立开发环境；运行 `npm test` 验证媒体流程。FFmpeg 默认使用程序目录 `程序组件/runtime/ffmpeg` 中的工具，也可通过 `FFMPEG_PATH` / `FFPROBE_PATH` 指定。

## 使用

1. 添加 B 站直播间号、完整链接或 b23.tv 分享链接，默认开启自动录制。房间卡片右上角 × 可移除监控，确认后关闭自动录制、等待当前写入结束，再从录制核心中移除；已录制素材和已导出的成片保留。
2. 在左侧选择正在录制的素材，播放、拖动时间轴或点“回到最新”。左右方向键逐帧定位；空格播放/暂停。
3. 输入起止时间（允许小数秒），或使用 I / O 设置当前起止点。设置后立即显示绿色起点旗帜、金色终点旗帜和时间标签；两端有效时显示选择区域，添加选段后仍保留标记。添加多个选段后可调整顺序。每个选段前有复选框，可单独勾选或全选；取消勾选会保留选段和排序，勾选状态自动保存。只合成勾选的选段，界面显示已选数量及总时长。
4. 右侧搜索普通聊天弹幕，点击内容跳到对应画面并暂停，点击垃圾桶从剪辑中排除，点击撤销恢复。礼物、粉丝团灯牌、上舰和付费留言不再采集、显示或进入新导出，过滤依据为事件类型，不屏蔽观众正常聊天中提到礼物的文字。
5. “导出选段”位于“添加选段”右侧，没有勾选时不可用。导出弹窗提供三种模式：纯净版本、弹幕版本、纯净 + 弹幕双文件版本，默认双文件。只生成所选模式的视频：纯净版或弹幕版各一个 MP4，双文件版两个 MP4。导出需要的字幕、分段和合并清单保存在临时目录，成功保存后清理；编码完成但保存失败时保留成片供重试；原始弹幕、选段和排除记录仍保存在项目内。弹幕版已把保留的弹幕叠进画面，普通播放器打开即可看到。弹幕版统一为 60 帧/秒，先进行帧率转换再逐帧绘制弹幕，纯净版保持原帧率。不再提供弹幕帧率开关。真人画面不会插值出新动作。双文件共用素材读取和剪辑范围；兼容的单源完整导出直接保留纯净版码流，弹幕版单独合成；其他情况共用解码后分别编码；不会把用户排除的弹幕或礼物加回来。导出读取点击时的编辑版本，后续修改不改变已提交任务。视频信息优先读取已索引的缓存，缺失时从内部素材重建短样本，不再依赖原始 FLV 路径；内部素材缺失时会显示具体原因。
6. 录制结束且所有源文件整理完成后，自动加入弹幕预处理队列；需要成片时手动导出。完整纯净版满足安全条件时直接码流复制，不重新编码；不兼容时使用现有回退。首版不自动导出完整纯净版，也不另建纯净版视频缓存。

右键已完成的素材 → 导出完整素材，仍可选择纯净版、弹幕版或双文件（默认）；忽略剪辑选段，沿用该素材的弹幕排除设置。正在录制或整理的素材不能完整导出。也可导入已有 FLV 和同名 XML，或持续跟踪仍在增长的 FLV。

完整导出的纯净版在单源、完整范围且 H.264/AAC 等条件兼容时直接重封装，保留原始视频与音频码流；无法安全直通时回退编码。弹幕版仍需合成到画面并保持 60 帧。单段结果省去重复合并，分片读取合并为批量传输；同盘保存避免再次复制整份成片。编码质量参数与原有硬件自动选择不变。

录完立即导出也会加速：已完成素材的弹幕版或双文件导出，范围达到一分钟且硬件编码可用时，最多同时处理两个视频块；按时间顺序合并，音轨统一处理。兼容的整场 AAC 音轨直接保留，不重复压缩。已有预处理缓存优先复用，缺失部分写入本次导出的临时目录，不受预处理缓存容量上限限制。纯净版、短片和软件编码沿用相应的单路流程。并行失败会先停止并等待两路退出，再用同一编码器顺序处理；硬件编码仍失败时回退软件编码，保存失败则保留已完成成片供重试。

同一段 65 秒、1080p60 实录素材的三轮对比中，两路处理比原单路缩短约 16%–21% 总耗时，未降低分辨率、帧率或编码质量参数。收益取决于显卡、素材和磁盘，不能据此保证两小时素材十分钟完成。后台预处理仍保持单任务，继续服务下一次导出。

## 录制完成后的后台预处理

默认开启“录制完成后自动预处理”。新录制素材完成整理后，在空闲时处理 60 帧弹幕视频并存入内部缓存；已经 ready 的不会重置。前台导出优先，预处理先让路。用户立即导出时仍复用已有块，只编码缺失或失效部分。纯净版手动完整导出保持安全码流复制路径，精确选段或不兼容整场可能需要编码。关闭自动预处理或单独暂停素材的设置有效。历史素材可右键手动加入预处理。

预处理完成后，完整弹幕版可直接复用视频缓存并处理音轨、封装成 MP4；切片复用范围内的完整缓存块，仅精确切点和缺失、失效部分需要处理。删除或恢复弹幕只使其实际显示范围涉及的缓存失效，普通选段调整保留其他缓存。纯净完整导出沿用兼容码流快速封装；纯净切片仍按精确剪辑流程处理，不额外保存第二套干净视频缓存。

预处理使用单个低优先级工作任务，录制、播放、音频波形分析和正式导出需要资源时暂停当前未完成块，保留已完成部分。可单独暂停/继续素材，或在设置关闭自动预处理。关闭软件窗口后后台仍可继续；电脑需保持开机且不进入休眠。程序退出后再次启动可复用已验证的缓存，不会恢复已取消的导出任务。

缓存位于数据目录的 render-cache，占用额外磁盘空间；预算为 20 GiB，开始新块前保留至少 2 GiB 可用空间。空间紧张时可回收未使用的旧缓存；当前素材无法完整放入预算时暂停，不反复丢弃并重新处理同一场内容。原片和待保存成片不参与缓存回收。删除素材会一并清理属于它的缓存。若缓存不可用，正式导出回退到普通处理流程；更改大量弹幕或处理尚未预备的范围仍需时间，不承诺任何机器都能十分钟导出整场。

## 素材管理

在左侧录像素材上点击右键（也支持 Shift+F10），选择“删除素材…”。二次确认后会永久删除本程序保存的该素材原片、同名弹幕、内部片段和旧自动归档，清除编辑记录并报告释放空间。正在录制、整理或导出的素材不能删除。已导出的成片、其他素材共享的文件以及外部导入的原文件保留。

删除还会清理本素材的 render-cache、可确认归属且已停止的临时工作区和数据库会话/源/预处理记录。核对被阻止（blocked）的过渡片段也在用户确认删除素材时清理；平时不会放宽核对后强行清理。已导出的纯净版、弹幕版及双文件均保留在导出目录，任务记录与素材解除关联后保留，只有另行确认删除该导出任务才删除对应成片。仅保留小型已删除原片路径凭据，避免延迟的录制事件重新导入已删除素材。

导出任务也支持右键（或 Shift+F10）→“删除导出任务…”。确认窗口会逐项列出将永久删除的成片；确认后同时移除对应文件与任务记录，原始素材、弹幕和剪辑选段保留。排队、处理、保存中或已有待保存成片的任务不可删除；保存失败时请先完成保存。文件被占用、已被替换或无法确认归属时会提示，并提供保留文件、仅移除记录的处理方式；取消确认不会删除文件。此操作不清空整个导出文件夹，也不删除其他任务的成片。

删除确认后直接清理，不提供回收站或恢复入口。文件被占用等情况下，设置中仅在需要时显示“清理未完成”和重试操作；后台空闲时自动继续，重启后仍可重试。

## 导出保存在哪里

右上角 **设置 → 默认导出文件夹 → 选择 → 保存导出目录**。EXE 会打开 Windows 文件夹选择窗口；浏览器版可以填写完整路径。默认是程序旁边的 `导出视频默认路径`。该设置是导出根目录，下面固定分为“完整素材”和“导出片段”。

片段和完整导出都会显示本次导出根目录，允许仅改变这次任务的目录。完整素材按「完整素材 / 日期 / 视频」，片段按「导出片段 / 日期 / 起止时间 / 视频」保存，不必再点下载。下方导出任务显示完整 MP4 路径，只提供“打开文件夹”入口，文件夹内只保留所选版本的 MP4。已经排队的任务保留提交时的目录，之后修改默认目录不会把它移走。

编码完成后的保存失败会显示“保存失败（编码已完成）”，可点击“重试保存”或“更换保存位置…”，无需再次编码。新的目录只影响该任务，不改变默认设置。目标子目录被移走时尝试重建，同名文件不覆盖；已编码的唯一成片和恢复记录不会当作过期缓存删除。

设置中展示两种成片目录；录像底部“完整素材”按钮打开完整版保存目录。已移除旧下载和自动归档入口。

所有名称使用北京时间和素材的实际录制时间，精确到分钟，与导出操作发生的时间无关：

```text
导出视频默认路径/完整素材/20260928/202609282130-2140.mp4
导出视频默认路径/导出片段/20260928/202609282130-2140/202609282130-2140.mp4
导出视频默认路径/导出片段/20260928/202609282130-2140/【弹幕版】202609282130-2140.mp4
```

完整录像按录制开始日期归档；切片按所选素材的开始日期归档。跨午夜的例子为 `完整素材/20260928/202609282350-202609290010.mp4`，午夜后单独选取的片段则归入 `20260929`。重复导出、同一分钟内多段或多个房间同名时自动增加 `_2`、`_3` 等序号，不覆盖已有文件。多选段合成时使用最早至最晚所选内容的时间范围，实际顺序和精确秒数保存在项目数据库的导出任务记录中；文件名不表示中间每秒都包含在成片中。

## 弹幕播放

时间轴使用两行：第一行在进度条内部叠加音频波形，保留播放游标、起终点旗帜和选段；第二行显示有效弹幕密度，点击可定位。两行名称位于图形上方左侧，靠左的起终点旗帜文字会避让名称，标记线仍指向实际时间。使用缩放按钮或两分钟视图查看短句与停顿，最细可查看十秒；下方横向拖动条在整场录像中移动查看窗口，也支持左右方向键、Home/End 和 PageUp/PageDown。一键回到全场或播放位置；两行、刻度和标记共用同一时间范围。横向浏览不改变播放位置和剪辑点，录制继续增长也不会拉伸已放大的窗口。波形只反映整体音量，包含背景音乐，不是自动人声识别。待分析、无音轨和读取失败会单独提示，不把缺失数据当作静音。

音频按需在后台以单任务、低进程优先级分析，缓存 100 毫秒峰值；只补算新增区间，不反复解码整场，也不另存一份音频。缓存保存在内部数据库，完成整理释放分片后仍可使用，删除素材时一并清理。密度按秒增量汇总全部已索引弹幕，不受右侧列表每次 500 条的展示上限影响。

内置过滤抽奖弹幕，不提供关闭开关。新版录制核心观察到天选时刻或红包抽奖的明确活动口令与有效时间时，仅对活动期间完全匹配口令的弹幕添加标记。列表、画面预览、弹幕密度和新导出统一排除这些弹幕，不折叠、不显示重复次数；普通重复弹幕全部正常保留。原始 XML 不删除；过滤统一应用于列表、预览、密度和新导出。旧素材没有活动标记、活动消息漏收或无法确认时保留，不按重复次数、关键词或未知消息类型猜测删除；正在录制的旧核心需在录制结束升级后才会写入标记。口令匹配不能区分同一活动期间恰好手动发送相同口令的普通聊天。

列表、画面预览、弹幕密度和新导出还会过滤整条都是 `[名称表情包_表情名]` 的占位消息（包括多个连续占位符），旧素材立即适用。普通方括号文字、Unicode emoji、带正文的混合消息以及普通重复弹幕保留；过滤始终开启。原始 XML 和数据库弹幕记录继续保留，已经导出的视频不会被改写。旧素材没有平台类型信息，因此此处按完整占位文本格式识别，不声称识别所有图片表情。

画面弹幕使用 Canvas、视频帧回调校时与 requestAnimationFrame 连续插值，按显示器刷新节奏移动。文字先渲染成可复用的位图，只遍历当前可见弹幕，避免每帧重新描边和测量；位图缓存最多 20 MiB，文字宽度最多缓存 2048 项。已录完的弹幕窗口复用，直播尾部持续更新，未录到的未来不会误认为已经缓存。暂停、拖动、播放速度和排除弹幕均同步，已有弹幕保持轨道，右侧搜索不再改变画面上的弹幕。窗口不可见或暂停时不持续运行绘制循环。系统启用“减少动态效果”时使用静止显示。密集弹幕会限制同时显示数量，完整弹幕仍保留。

桌面壳源码位于 `desktop`。在项目根目录执行 `live-editor/desktop/build.ps1 -DotNet .tools/dotnet/dotnet.exe`，将生成的 `live-editor/desktop/package` 中全部文件按相对目录结构复制到程序根目录。WebView2 官方 NuGet 依赖固定为 1.0.4191.47，许可文件随桥接 DLL 发布。桌面壳缩小减少的是磁盘、分发和启动解包成本，不代表运行时的内存占用同比缩小。

## 从 Git 仓库准备开发环境

建议使用 Git 克隆并保留历史；录制核心构建使用 GitVersion。

```powershell
git clone --recurse-submodules https://github.com/kk12091209/-.git caibo
cd caibo/live-editor
. ./scripts/dev-env.ps1
npm ci
```

开发需要 Node.js 24+ 和带 libass / libx264 的 FFmpeg、FFprobe。可把已下载 Release 的“程序组件/runtime”复制到源码根目录的“程序组件/runtime”，或设置 FFMPEG_PATH、FFPROBE_PATH、RECORDER_PATH 指向对应工具。只复制运行时，不要把正式 data 复制进开发环境。默认开发数据和端口独立，见下文“开发和清理”。

```powershell
$env:FFMPEG_PATH = '<FFmpeg完整路径>'
$env:FFPROBE_PATH = '<FFprobe完整路径>'
npm test
npm run test:dev
npm run build
npm run dev
```

构建 Windows 录制核心需要 .NET 8 SDK；从仓库根目录运行：

```powershell
. ./live-editor/scripts/dev-env.ps1
dotnet publish ./BililiveRecorder.Cli/BililiveRecorder.Cli.csproj -c Release -r win-x64 --self-contained true -o ./.tools/public-runtime/recorder
./live-editor/desktop/build.ps1 -DotNet dotnet -OutputDirectory ./.tools/public-desktop
```

发布脚本的 RuntimeRoot 中还需 node/node.exe（固定 Node 24.12.0）；详见[发布说明](docs/RELEASE.md)。源码 ZIP 中的 SOURCE-README.md 记录 Git 基线与子模块恢复方式。

## 数据位置

普通用户根目录只有 `录播机.exe`、`使用说明.txt`、`程序组件` 和 `导出视频默认路径`。开发电脑额外将 Git 仓库、源码、构建工具与分享包统一放在 `源码`，不会混进普通用户运行包。

录制和剪辑所需的内部业务数据默认位于 `程序组件/live-editor/data`：

- `originals`：官方录制核心生成的原始 FLV、同名 XML 和本地配置。即使剪辑失败也保留。
- `chunks`：录制中按约一秒媒体时间保存的内部数据，非独立小视频。仅本版本启用后新开始、由实时录制事件登记的素材，正常录制结束后后台核对完整原片与这些分片的媒体字节、关键帧及编码信息，建立原片字节索引；确认读取切换且旧读者退出后自动删除对应分片实文件，只保留小型数据库索引。
- `editor.sqlite`：连续会话、关键帧索引、弹幕和编辑记录；备份时应退出编辑服务并同时保留 WAL 文件，或使用 SQLite 备份工具。
- `archives`：仅保留旧版本生成的完整归档，不再自动产生新副本；删除对应素材时会一并清理本程序的旧归档。
- `temp`：探测、字幕合成和导出的临时工作文件，随数据目录所在磁盘保存。正常结束或编码失败后清理；编码完成但保存失败的成片持久保留，重新启动后仍可重试保存，保存成功后清理。异常退出残留仅在确认属于本程序、原服务及登记的子进程均已退出后自动清理；陌生文件和仍被使用的目录保留。

一秒片段在完整数据包写入后发布；最后不足一秒的部分在结束时发布。每次只读新增数据，不会为了更新时间轴反复合并整场。剪辑是选段和排除记录，不改原文件。新录制正常完成后无需导出一遍来释放分片，也不需要重新编码或复制一份原片；从原始 FLV 直接回看、精确剪辑和导出。原始弹幕、排除记录与编辑数据库继续保留。录制核心的全局与现有房间配置均固定为只采集普通聊天；导入旧 XML 时只索引普通聊天，数据库里已有的历史礼物记录也不会进入查询和新导出。

## 已验证的边界与当前限制

- 自动化测试覆盖原始 FLV 不在原路径时仍能从内部素材读取视频信息和导出、三种输出模式、勾选状态保存及仅导出勾选片段；还覆盖：跨关键帧的秒级分段重建、完整解码、文件增长与索引恢复、跨原文件导出、切片跨断流空缺拒绝、整场导出跳过未录到的空缺、原片字节一致、弹幕排除与撤销记录、乱序事件、遗漏事件恢复、本机 HTTP 预览与跨站来源限制。
- 首版编辑器支持 H.264/AVC 的 FLV。默认优先请求 AVC，实际画质取决于 B 站提供的权限。本版暂不提供账号登录设置；画质由平台实际返回的直播流决定。
- 原始码流不转码；预览和精确剪辑需要 FFmpeg 转码，使用较低进程优先级；预览使用两个编码线程，导出优先实测可用的硬件编码器，失败后整次重做为 CPU 编码，CPU 编码线程按本机核心数留出余量（总计最多六个）。每次预览最多读取 90 秒，播放到末端会继续读取下一窗口，避免暂停时持续下载整场。预览上限 1280 宽，不代表原片分辨率。不承诺端到端一秒延迟，也尚未完成多小时/多房间负载测试。
- 分段是时间桶，帧和音频包不会被从中间切断，所以边界有包粒度误差；每个片段可能依赖更早关键帧，不能直接单独交给外部播放器。
- 断流后文件自动加入同一活动会话。存在真实空缺时，预览跳过空缺，片段跨空缺会提示分别选段，整场导出拼接已有内容而不补造缺失画面。编码参数发生变化时的整场导出仍需要更多实流验证；主动删除素材前，原文件会保留。
- 新增文件扫描可找回编辑服务不在时错过的事件，但不能恢复上游或网络从未录到的数据。崩溃留下不完整尾包会保留原片并显示错误。
- 右侧列表每次最多显示当前范围/搜索结果的 500 条，原始弹幕完整保存。ASS 是基础滚动布局，未复刻 B 站所有弹幕样式。
- 升级前历史素材不会自动登记或批量清理。录制过程中暂存原片和一秒分片；正常结束、校验与读取切换完成后自动释放重复分片，不再生成第三份完整归档。原片缺失、截断、内容不符、外部导入或仍有读者使用时保留必要分片，避免丢失唯一可编辑素材。外部导入文件不属于程序管理，默认保留内部分片。确认删除素材仍会清理本程序原片与相关内部数据，导出成片独立保留。
- 录制核心只绑定本机 17861 并使用随机认证；工作台只绑定本机 17860。不要把这两个端口代理到公网。本版没有登录信息填写或保存接口。

## 性能与空间

弹幕预览按照显示器刷新节奏绘制，弹幕成片固定 60 FPS。导出自动探测可用硬件编码器，失败后回退到 CPU；普通用户无需选择显卡品牌。软件同时限制编码线程和预览窗口长度，优先保留录制资源。具体耗时和内存取决于分辨率、弹幕密度和电脑配置，尚未完成低配电脑和多小时压力测试。

开发 SDK、node_modules、构建缓存不会进入用户运行包。录像数据单独保存在 data。分片的自动释放由完整性校验和读取租约控制；正在录制或校验未通过时，不能手动把 chunks 当作普通缓存删除。

开发或测试时，请在项目所在磁盘的 `live-editor` 目录打开 PowerShell，先点调用环境脚本：

```powershell
. .\scripts\dev-env.ps1
npm ci
npm run build
npm test
```

开发界面运行 `npm run dev`，默认访问 http://127.0.0.1:17962 ，API 和独立录制核心分别使用 17960 / 17961。数据与默认导出均在源码仓库的 `.tools/development-app` 内，开发界面的代理也只连接该开发服务。仅启动 API 可运行 `npm run dev:server`；已有 `dist` 时可访问 17960。需要演示素材时另开终端运行 `npm run demo`，脚本先校验服务返回的数据目录，匹配后才生成和导入测试视频。

可使用 `DEV_PROJECT_ROOT`、`DEV_EDITOR_PORT`、`DEV_RECORDER_PORT`、`DEV_UI_PORT` 调整独立环境；demo 须使用一致设置。`DEV_NO_RECORDER=1` 可用于仅测试导入/剪辑。开发入口忽略正式 `EDITOR_*` 数据/端口设置，拒绝正式端口 17860/17861。`npm run test:dev` 验证隔离规则。原 `npm start` 保留为底层服务入口，沿用 `EDITOR_DATA` 等设置；开发测试应使用 `npm run dev`，不要将 `npm start` 当作隔离入口。

脚本只给当前 PowerShell 窗口及其后续子进程设置 TEMP/TMP、npm 缓存、NuGet 包和 .NET CLI 目录，全部放在项目根目录的 `.tools` 下；不修改用户级或系统级环境，不移动共享缓存，也不改变已运行软件的数据位置。关闭窗口后这些环境设置失效。从其他源码副本使用时，可显式传入 `-ProjectRoot`。

发布工具下载默认位于 `.tools/release-tools`，打包工作目录默认 `.tools/release-work`，解压验证默认使用 `.tools/release-qa` 下的独立目录；最终分享目录只需复制完成的发布文件。现有 `-Destination`、`-ToolsRoot`、`-OutputRoot` 参数仍可覆盖默认位置。许可证收集按显式 `-NuGetRoot`、当前 `NUGET_PACKAGES`、项目包缓存、已有用户包缓存的顺序只读查找，不会为打包迁移整个共享 NuGet 缓存。

## 精简发布

发布方式与可复现打包命令见 [发布说明](docs/RELEASE.md)。运行包与源码 ZIP 分别提供，使用软件只需下载运行包。运行包只收录必要组件，不包含已有录像、Cookie、数据库、浏览器资料、node_modules、SDK 或构建缓存；两个默认视频目录由打包脚本新建为空目录，不从开发电脑复制内容。

打包支持源码和运行组件分开放置：`-ProjectRoot` 指向源码仓库，`-AppRoot` 指向其中的 `live-editor`，`-DesktopRoot` 指向最新桌面构建输出；`-RuntimeRoot` 可指定包含 `node`、`recorder` 的运行时目录。不指定时依次检查项目下的 `程序组件/runtime`、`runtime` 和项目父目录的 `程序组件/runtime`。工具与构建临时目录默认留在源码仓库的 `.tools` 内。

组件清单位于 `程序组件/release-manifest.json`，路径仍相对于整个解压目录，支持中文目录的逐文件 SHA-256 校验。发布验证同时检查顶层四项、空视频目录、隐私排除，以及随包 Node SQLite 和 FFmpeg 软件编码。录制核心、预览和导出仍具备完整功能。硬件编码自动选择和回退，用户界面统一呈现导出结果，不显示显卡品牌。

起点前的切换控件可选择“视频时间”与“录制时间”，与选段输入和操作按钮排列在一起。录制时间使用北京时间，默认对应当前选段的日期；选择日期、时分秒后自动暂停并定位到对应画面，支持跨午夜。切换格式保留选段位置，超出已录范围或落在断流空缺会提示；本地导入素材没有可靠开录时间，使用视频时间定位。

界面按可用窗口尺寸适配：较矮的笔记本窗口会降低播放器高度，为时间轴和选段操作留出空间；较窄时控件分组换行。顶部“素材”和“弹幕”可随时展开或收起对应侧栏，宽度不超过 1100 像素时默认收起素材栏。手动切换侧栏后，本次界面内保持该选择；展开和收起不会改变当前素材、播放位置或剪辑记录。
